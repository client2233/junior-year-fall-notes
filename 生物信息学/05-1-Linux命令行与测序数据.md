## 7.1 数据有多大：为什么 Excel 不行

一个 30× 的人类全基因组重测序（WGS）数据，拿去数里面的 reads：

- 约 **6–10 亿条** reads（取决于读长）
- 存成 FASTQ 再 gzip 压缩，仍有**数十 GB**
- Excel 最多只能打开 **1,048,576 行** —— 连千分之一都装不下

粗算（课件原式）：$3.1\ \text{Gb}\times 30 / 150\ \text{bp}\approx 6\times10^{8}$ 条 reads，每条 4 行 ≈ **24 亿行**。

> **要点** 这里的「30×」指测序深度：人全基因组重测序检测变异时，30× 是常用标准深度。深度 = 覆盖基因组的总碱基数 ÷ 基因组大小。

Excel 那 1,048,576 行 = $2^{20}$，是硬上限，不是配置问题。数据一旦超过这个量级，**命令行和脚本是唯一选择**。

## 7.2 Read 与两种测序技术

**Read（测序读段）**：测序仪从单个核酸（DNA / RNA）片段上直接读取并输出的一段连续碱基序列，是测序实验输出的**最基本、最原始的数据单元**。

比喻：把基因组比作一部大部头，建库过程就是把它撕成无数随机小碎片（fragment），测序仪读出的每一小段文字就是一个 read。

| | 短读长（Short Reads） | 长读长（Long Reads） |
|---|---|---|
| 平台 | 二代测序 NGS：Illumina、BGI | 三代测序 TGS：PacBio、Oxford Nanopore |
| 长度 | 50–300 bp | 几千 bp ～ 上百万 bp |
| 准确率 | 单碱基错误率通常 < 0.1% | 单碱基错误率较高（但可自纠错） |
| 通量 | 极高 | 较低 |
| 典型用途 | 变异检测（SNP / Indel）、基因表达定量 | 基因组从头组装（de novo assembly）、全长转录本、大型结构变异（SV） |

长读长的核心优势是**能跨越高度重复的基因组区域** —— 短读长在这些区域无法唯一定位。

## 7.3 生物数据大多是纯文本

格式不多，先认清三种。

### 7.3.1 FASTA

标题行以 `>` 开头，接着是序列行：

```
>NM_000546.6 Homo sapiens tumor protein p53 (TP53), transcript variant 1, mRNA
CTCAAAAGTCTAGAGCCACCGTCCAGGGAGCAGGTAGCTGCTGGGCTCCGGGGACACTTTGCGTTCGGGC
TGGGAGCGTGCTTTCCACGACGGTGACACGCTTCCCTGGATTGGCAGCCAGACTGCCTTCCGGGTCACTG
```

**一条序列恰好有一个 `>` 标题行** —— 这个性质是后面所有「数序列」命令的基础。

### 7.3.2 FASTQ：每 4 行一条 read

```
@SIM.1 length=100
TGAAGTTAACCACAGTCGGGAAACAAGCATAGAAATGGAAGAAAGTGA…
+
;BED>?C=A;B<BGGF:C?;BDJ@FI?@>D?DD;???<<A;=CB?96?…
```

| 行 | 内容 |
|---|---|
| ① `@` 开头 | read 名称 |
| ② | 碱基序列 |
| ③ `+` | 分隔行 |
| ④ | 质量值，**每个字符对应一个碱基** |

**质量值怎么读（Phred+33）**：$Q = \text{字符的 ASCII 码} - 33$，碱基测错的概率

$$
P_{\text{err}} = 10^{-Q/10}
$$

- `I` → $73-33=40$ → 错误率 $10^{-4}=1/10000$
- `@` → $64-33=31$

常见档位：Q20（99% 正确）、Q30（99.9%）、Q40（99.99%）。测序报告里说的「Q30 比例」，就是质量值 ≥ 30 的碱基占比。

> **要点** 记住 `@` **同时是 read 名称行的首字符和质量值行的合法字符（Q31）**。7.7 的陷阱题就栽在这上面。

## 7.4 为什么是 Linux

- 服务器、超算集群几乎都跑 Linux；
- 大多数生信软件**只提供 Linux 版本**：BWA、samtools、GATK、STAR……
- 写成脚本后能自动处理成百上千个样本 —— 这才是编程的意义；
- 免费开源（1991 年 Linus Torvalds 发布）；发行版选 **Ubuntu** 即可。

上手方式：

- **Windows**：管理员身份运行 PowerShell，执行 `wsl --install`，即得 Ubuntu（WSL2）；
- **macOS**：自带终端，大部分命令相同；要跑重型分析就 `ssh` 登录 Linux 服务器。

## 7.5 核心命令：记住这十几个就够用

| 命令 | 作用 | 例子 |
|---|---|---|
| `pwd` / `ls` / `cd` | 在哪 / 有什么 / 去哪 | `cd data; ls -lh` |
| `mkdir` / `cp` / `mv` / `rm` | 建目录 / 复制 / 移动 / 删除 | `mkdir results` |
| `head` / `tail` / `less` | 看开头 / 看结尾 / 翻页看 | `head -5 seqs.fa` |
| `wc -l` | 数行数 | `wc -l seqs.fa` |
| `grep` | 按模式查找行；`-c` 计数 | `grep -c ">" seqs.fa` |
| `zcat` | 不解压直接读 `.gz` | `zcat x.fastq.gz \| head -8` |
| `tar -zxvf` | 解压 `.tar.gz` | `tar -zxvf tool.tar.gz` |

> **要点** 所有命令都有 `--help` 或 `man`。生信里的命令不需要背全，只要知道「有这么个工具」，用的时候查。

## 7.6 管道 `|`：把小工具像积木一样串起来

```
zcat sample.fastq.gz  →  wc -l  →  ÷ 4  =  reads 数
```

```bash
zcat data/sample.fastq.gz | head -8          # 看前两条 read
grep ">" data/seqs.fa | head -3              # 只看标题行
echo $(( $(zcat data/sample.fastq.gz | wc -l) / 4 ))
```

前一个命令的输出直接作为后一个命令的输入。**不产生中间文件**，几十 GB 的数据也能一行处理。

## 7.7 例题 1 与「看起来合理」的陷阱

**例题 1**：这个 FASTA 里有几条序列？

```bash
grep -c ">" data/seqs.fa
# 8
```

每条序列恰好有一个 `>` 标题行 → 数标题行就是数序列。

**陷阱题**：FASTQ 每条 read 的标题都以 `@` 开头，那

```bash
zcat data/sample.fastq.gz | grep -c "@"
```

就能数出 reads 数，对吗？

**不对。** 实测两个结果对不上（已实跑核对）：

| 方法 | 命令 | 结果 |
|---|---|---|
| 数含 `@` 的行 | `zcat sample.fastq.gz \| grep -c "@"` | **19,999** |
| 总行数 ÷ 4 | `echo $(( $(zcat sample.fastq.gz \| wc -l) / 4 ))` | **10,000** |

原因：**质量值行里的 `@` 也是合法字符（Q31）**，被 `grep` 一起数进去了。这份数据里质量行恰好贡献了 9,999 个 `@`。

> **要点** 这一页是第 1 节最重要的一个易错点，三条结论要记牢：
> 1. **先理解文件格式，再写命令**；
> 2. 「结果看起来合理」**不等于**正确 —— 19,999 和 10,000 都像人话，只有对照才知道哪个错；
> 3. 「总行数 ÷ 4」**最稳妥**。用 `grep -c "^@SIM"` 在本例能行（read 名统一前缀），但真实数据的 read 名前缀各不相同，不能依赖。

底层的验证办法：`zcat ... | wc -l` 得到 40,000 行，40,000 ÷ 4 = 10,000，与「总行数 ÷ 4」一致 —— **用第二种独立方法交叉验证**是生信里的日常操作。

## 7.8 PDB 也是文本：用 grep 探索蛋白质结构

同样一套 grep 管道，换到蛋白质三维结构文件上（数值均已实跑核对）：

```bash
grep -c "^ATOM" data/4hhb.pdb                    # 原子行 → 4,384
grep "^ATOM" data/4hhb.pdb | grep -c " CA "      # Cα 原子 = 氨基酸残基数 → 574
grep "^HETATM" data/4hhb.pdb | grep " FE "       # 血红素中的铁 → 4 行
grep "^ATOM" data/4hhb.pdb | cut -c22 | sort -u  # 有哪几条链 → A B C D
```

- `4HHB` = 人血红蛋白，$\alpha_2\beta_2$ 四聚体；
- `cut -c22`：取第 22 列（链编号）；
- `HETATM` = Heteroatom（杂原子），专门记录非标准生物大分子链中的原子三维坐标及相关信息。

574 个 Cα ÷ 4 条链 ≈ 143 —— 与四条链的实际残基数（141 / 146 / 141 / 146）吻合，量级正确。

第 3 节会用 Python 细看这些结构（见 [[05-3-结构与组学数据·PDB与单细胞]]）。

## 7.9 conda：给每个项目一个独立环境

**问题**：软件 A 要 Python 3.9，软件 B 要 3.12；一个系统装不下两套。

**conda** 为每个项目建一个「隔离的房间」。**bioconda 频道**里有上万个生信软件，一行安装。推荐装 **Miniforge**（默认使用 conda-forge）。

```bash
conda create -n bio -c conda-forge -c bioconda samtools seqkit
conda activate bio      # 提示符变成 (bio)
seqkit stats data/seqs.fa
conda deactivate
conda env list          # 查看所有环境
```

**易错**：没激活环境就装包、运行 → 养成先看提示符里有没有 `(bio)` 的习惯。环境没激活时装的包装到了 base，跑的时候又找不到，是这个阶段最常见的翻车方式。

> **补充** Docker 是更彻底的隔离（连系统库一起打包），后续课程再讲。区分一下：conda 解决的是**软件依赖**冲突，Docker 解决的是**整个运行环境**的可复现性。

### 第 1 节作业

| 编号 | 题目 | 数据 / 提示 |
|---|---|---|
| 1 | 统计 `seqs.fa` 中标题含「BRCA」的序列条数 | `seqs.fa`；`grep \| grep -c` |
| 2 | 用 grep 统计 4HHB 的原子行、Cα 数、铁原子数和链编号 | `4hhb.pdb`；`cut -c22 \| sort -u` |

**练习 1 解答**（已实跑）：

```bash
grep ">" data/seqs.fa | grep -c "BRCA"
# 2
```

该文件里 `BRCA1` 与 `BRCA2` 各一条，所以答案是 **2**。注意不能写成 `grep -c "BRCA" data/seqs.fa` —— 虽然这题的库里只有标题行含「BRCA」所以结果一样，但一旦序列正文里出现 `BRCA` 子串就会误计，**先取标题行再计数**才安全。

**练习 2 解答**：见 7.8 的四条命令，答案是 4,384 / 574 / 4 / A B C D。
