# 07-4 多序列比对与 ClustalW

到这里链条闭合了一半：距离矩阵 → 树需要**比对**作为输入，而比对本身又需要**树**来定合并顺序。这是个循环依赖，ClustalW 的解法是「先粗后细」—— 用成对距离建一棵**指导树**，再按这棵树的顺序做渐进式比对。树是近似的，比对就跟着近似。

## 18.1 什么是多序列比对

**定义** 给定 $N\ge3$ 条序列，在它们中间插入空位（gap），使等长后**同一位点上的字符最大程度同源**。数学上就是一个 $N\times L$ 的字符矩阵，每行去掉 gap 后还原为原序列。

比对质量的两个直观指标：

| 指标 | 含义 |
|---|---|
| 保守列（conserved column） | 该列所有序列字符相同 —— 通常对应结构或功能上的关键位点 |
| 一致性（consistency） | 该列最常见的字符所占比例，按列给出 0–9 或 0–* 的分级 |

- 保守列 → 用来定位活性位点、设计简并引物、推断位点约束；
- 一致性的**低值列** → 通常是高变区或比对不可靠区，建树前应当剔除（见 [[07-1-分子进化·系统树与距离矩阵]] 15.8）。

> **补充** MSA 没有「唯一正确答案」。同一个数据集换 gap 罚分、换打分矩阵、换算法，会得到不同的比对，而**这些比对都能自圆其说**。所以 MSA 的可靠性只能用外部证据检验（结构叠合、基准数据集 BAliBASE/PREFAB、或多种算法的**共识**），不能用「看起来整齐」来判断。

## 18.2 为什么 MSA 比双序列比对难得多

双序列比对是 $O(L^2)$ 的动态规划，有精确解。多序列比对的精确 DP 需要 $O(L^N)$ 空间与时间：

| $N$ | $L=100$ 时的状态数 |
|---|---|
| 2 | $10^4$ |
| 5 | $10^{10}$ |
| 10 | $10^{20}$ |

而且，即使用启发式把状态压下去，**目标函数本身**也是问题：

**SP 打分（sum-of-pairs）** 把比对得分定义为所有序列对的得分之和

$$
S(\text{MSA})=\sum_{1\le p<q\le N}\text{score}(s_p,s_q)
$$

在 SP 目标下，MSA 的精确最优是 **NP-hard**（Wang & Jiang 1994）。所以所有实用算法都是启发式 —— 这不是工程偷懒，是复杂度决定的。

> **补充** SP 打分本身也有偏差：它给「序列多、分歧大」的比对更高分，会偏好把 gap 集中到少数序列上（"gap spreading" 的反面）。因此后来的方法（如 COFFEE、T-Coffee）改用**一致性目标**：先做成对比对，再让 MSA 尽量与这些成对比对一致。

## 18.3 方法分类

| 类别 | 代表 | 思路 | 弱点 |
|---|---|---|---|
| 渐进式 | ClustalW、Clustal Omega | 按指导树顺序两两/组组合并 | 早期错误无法回溯 |
| 迭代优化 | MUSCLE、MAFFT | 先给初始比对，再拆分重组改进 | 可能陷入局部最优 |
| 一致性 | T-Coffee、ProbCons | 用成对/局部比对的一致性作为目标 | 慢，内存大 |
| 图方法 | POA、spoa、abPOA | 把比对建成 DAG，逐条加入序列 | 适合长读长纠错、大量近缘序列 |
| Profile 搜索 | PSI-BLAST 的 PSSM | 把一族序列压成位置特异性矩阵去搜库 | **不是 MSA 构建器** |

最后一行是课件特意强调的：**PSI-BLAST 的主要任务是迭代式蛋白质数据库搜索**，它内部确实做了「多序列比对 → profile」这一步，但那个比对是副产品，质量和专门的 MSA 工具没有可比性。见 [[07-5-PSI-BLAST·PSSM与位置特异性打分]]。

## 18.4 ClustalW：三步流程

Thompson, Higgins & Gibson (1994)。流程极简：

```text
1. 所有序列两两比对（full DP）→ 得到成对距离 → 距离矩阵
2. 用 NJ（不是 UPGMA）建指导树 guide tree
3. 按指导树从叶到根，逐步做 序列–序列 / 序列–profile / profile–profile 比对
```

三个细节值得停一下：

**(1) 第 1 步用的是完整动态规划，不是 k-mer 启发式。** 所以 $N$ 条序列要做 $\binom{N}{2}$ 次 DP，$N=1000$ 时就是 50 万次 —— 这是 ClustalW 慢的根源。Clustal Omega 用 mBed 把这一步降到近线性。

**(2) 第 2 步用 NJ 而不是 UPGMA。** 因为指导树只需要「谁先合并」的顺序，不需要等距；NJ 不要求分子钟，对速率不均更稳。

**(3) 第 3 步的错误不可逆。** 一旦某一步插入了 gap，后面的比对只能在这个骨架上继续插 gap，**永远不会把已插入的 gap 删掉**。这就是经典的 "once a gap, always a gap"。

## 18.5 序列赋权

渐进式比对里，先合并的是**最相似**的序列。如果一组高度相似的序列（比如同一蛋白的 20 个菌株变体）先合并，它们会主导 profile 的每一列，让其他分歧较大的序列被"挤"成 gap。所以要给每条序列一个权重，**降低冗余序列的影响**。

### 18.5.1 ClustalW 的枝权

ClustalW 从指导树直接算权重：一条序列的权重 = 它自己所在枝的权重 + 沿路径到根经过的每条枝的权重**除以该枝下方的序列数**。

课件给了一个具体算例（某条序列，路径上经过 5 条枝）：

$$
w=0.081+\frac{0.226}{2}+\frac{0.061}{4}+\frac{0.015}{5}+\frac{0.062}{6}
$$

**解读**：$0.081$ 是这条序列自己的末端枝；$0.226$ 是它与最近姊妹共有的父枝，除以 2 是因为那枝下方有 2 条序列（两条序列共享这段历史，各分一半）；再往上 $0.061$ 下方 4 条、$0.015$ 下方 5 条、$0.062$ 下方 6 条。**分母 = 该枝下方的序列数**，这正是「冗余折价」的机制：一个 20 条近缘序列的分支，其枝长贡献被 20 除，不会因为序列多就压过其他分支。

> **订正** 按课件自己给出的这五个数求和，结果是 $0.081+0.113+0.01525+0.003+0.010333=0.2226$，与课件写的 $0.221$ 差 $0.0016$。原因是五项各自先四舍五入到三位小数。**记公式，不要记这个数。**

### 18.5.2 与 Henikoff 权重的区别

| | ClustalW 枝权 | Henikoff 位置权重 |
|---|---|---|
| 依据 | 指导树的枝长与拓扑 | 比对本身的列（与树无关） |
| 输入 | 树 | 只用 MSA |
| 用在 | 渐进式比对的打分 | profile 的构建（07-6） |

两套权重解决同一个问题（冗余折价），但一个用树的全局信息，一个只用列的局部信息。Henikoff 的好处是不依赖树，因此可以在 profile 比对里反复使用。

## 18.6 动态规划的打分函数

渐进式比对的核心仍是 DP，只是「一个位置」从单个字符变成了**一列**（一个 profile 列）。打分函数：

$$
\text{score}(i,j)=\sum_{n=1}^{N}W_n\,M\!\left(A_{n,i},\,A_{n,j}\right)
$$

| 符号 | 含义 |
|---|---|
| $M$ | 替换打分矩阵，PAM 或 BLOSUM |
| $W_n$ | 第 $n$ 条序列的权重（18.5） |
| $A_{n,i}$ | 第 $n$ 条序列在第 $i$ 列（profile 列）的字符；若该序列在这一列是 gap，则这一项为 0 |

**这就是 profile–profile 打分**：不是比两个字符，而是比两列字符分布，并按权重加权。[[07-6-sequence-profile与profile比对]] 会把同一个式子推到 $20\times20$ 的频率形式。

### 18.6.1 Gap 罚分是位置特异的

ClustalW 的关键改进（相对 ClustalV）就是 gap 罚分不再全局固定，而是随位置调整：

| 情形 | 调整 |
|---|---|
| 该列没有 gap，且残基多为亲水（G, P, S, T, N, D, Q, E, K, R） | 开 gap 罚分 ×0.5（亲水区更容易容忍插入/缺失） |
| 该列已有 gap（相邻位置） | 开 gap 罚分 ×2（避免 gap 连成片） |
| 该列 gap 比例 >50% | 延伸罚分调高 |
| gap 落在疏水残基之间 | 延伸罚分调高（疏水核心不容忍 indel） |

这套启发式的物理依据是：**indel 在结构上比替换代价高**，尤其在疏水核心与二级结构元件内部。所以「哪里允许 gap」这件事，ClustalW 用残基的理化性质做了先验。

## 18.7 渐进式的根本缺陷

三个必须记住的失败模式：

**(1) 早期错配被永久固化。** 假设 A、B 两条序列因为一段低复杂度区被错误对齐，它们先合并成一个 profile；之后所有与这个 profile 比对的序列都被迫接受这个错误骨架。这就是课件说的「早期产生的错配通常不会在后续步骤中自动纠正」。

**(2) 指导树的错误会传染。** 指导树是 NJ 在成对距离上算的，而**成对距离来自成对比对** —— 成对比对本身就可能错。所以错误链条是：成对比对错 → 距离错 → 树错 → 合并顺序错 → MSA 错。

**(3) 对 $N$ 大的数据集，先合并的近缘序列会「锁死」整段比对。** 这是为什么 ClustalW 在 >200 条序列时质量明显下降，而迭代法（MUSCLE、MAFFT）能救回来 —— 它们允许把已经合并的组**拆开重新比对**。

> **补充** MUSCLE 的三阶段（k-mer 距离 → 渐进式初稿 → 迭代精修）与 MAFFT 的 L-INS-i（一致性 + 迭代精修）本质都是在补 ClustalW 的这个洞。代价是慢。实践建议：$N<200$ 用 MAFFT L-INS-i；$N$ 上千用 MAFFT FFT-NS-2 或 Clustal Omega；只有需要「可解释的合并顺序」时才用 ClustalW。

## 18.8 实操要点

```bash
# ClustalW 的现代替代：Clustal Omega（快得多，输出兼容）
clustalo -i input.faa -o aln.faa --outfmt=fasta --threads=8

# MAFFT：高精度模式（慢）
mafft --localpair --maxiterate 1000 input.faa > aln.faa

# 按列剔除低质量区（gap 比例 >20% 的列）
trimal -in aln.faa -out aln.trim.faa -gt 0.8
```

四个参数值得记：

| 参数 | 建议 |
|---|---|
| 打分矩阵 | 分歧度低用 BLOSUM80/PAM20，高用 BLOSUM45/PAM250；蛋白默认 BLOSUM62 |
| gap open | 默认 −10 左右；结构域边界已知时调大 |
| gap extend | 默认 −0.2（Clustal 系列）或 −1（BLAST 系列）；长 indel 多时调小 |
| 输出格式 | 下游建树要 fasta 或 phylip；profile 要 Stockholm（带列注释） |

## 订正

**1. 第 9 页的权重算例，五项之和不等于所写的 0.221。**

$$
0.081+\frac{0.226}{2}+\frac{0.061}{4}+\frac{0.015}{5}+\frac{0.062}{6}
=0.081+0.113+0.01525+0.003+0.010333=0.2226
