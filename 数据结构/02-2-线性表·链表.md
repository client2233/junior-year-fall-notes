# 02-2 线性表·链表

> 系列：[[01-数据结构与算法概论]] · [[02-1-线性表·顺序表]] · [[02-2-线性表·链表]] · [[03-栈与队列]] · [[04-串]] · [[05-数组与特殊矩阵]]

换一种存储映射：不用连续内存，用**指针**把离散的结点串起来。代价表整个翻转——按位访问从 $O(1)$ 掉到 $O(n)$，表头插删从 $O(n)$ 升到 $O(1)$。

## 3.1 链式存储与结点

**定义** 用一组**任意**（可连续也可离散）的存储单元存放元素，元素之间的逻辑关系由**指针**表示，称为**链式存储**。

**结点（node）** 由两部分组成：

| 域 | 内容 |
|---|---|
| 数据域（data field） | 元素值本身 |
| 指针域（pointer field） | 后继（以及前驱）结点的地址 |

**与顺序存储的分水岭**：顺序存储里"第 $i$ 个"是**算出来**的（地址算术）；链式存储里"第 $i$ 个"是**数出来**的（走 $i$ 步）。这一条决定了两者全部复杂度差异。

**代价**：每个结点多一个指针的空间开销。$32$ 位机上存 `int`，空间利用率只有 $50\%$。

> **补充（存储密度）** 教材用**存储密度**衡量这个开销：

$$
\text{存储密度} = \frac{\text{数据本身占的存储量}}{\text{结点占的总存储量}} .
$$

> 存 `int` 的单链表是 $4/8 = 0.5$；顺序表是 $1$。所以链表的"省空间"是指**不预留冗余容量**，不是说单位元素占得少——恰恰相反，它单位元素占得更多。

## 3.2 单链表

每个结点只有一个指针，指向直接后继。

```cpp
struct LNode {
    int   data;        // 数据域
    LNode *next;       // 指针域，指向直接后继
};
typedef LNode *LinkList;
```

**术语**：

| 术语 | 含义 |
|---|---|
| 首结点 | 第一个存数据的结点 |
| 尾结点 | 最后一个结点，`next == nullptr` |
| 头指针 (head) | 指向链表开始位置的指针，**链表的唯一标识** |
| 空表 | 没有任何数据结点 |

### 3.2.1 头指针 vs 头结点（关键区分）

课件只讲了**头指针**，而教材的实现用的是**带头结点**的版本，两者不是一回事：

| | 头指针 | 头结点 |
|---|---|---|
| 是什么 | 一个指针变量 | 一个**真实的结点**，位于首结点之前 |
| 存数据吗 | —— | **数据域不存有效元素**（可存表长等信息） |
| 空表怎么表示 | `head == nullptr` | `head->next == nullptr` |
| 是否必需 | **必需**（没有它找不到链表） | **可选**（是实现的约定） |

**带头结点的三个好处**：

1. **空表与非空表的操作统一**。空表也有一个结点存在，`head` 永不为空，插入第一个元素不用改 `head` 本身。
2. **首结点与其他位置的插删统一**。在第 $1$ 个位置插入时，它的"前驱"就是头结点，于是所有插入都是"在某个结点之后插入"，不需要为 `i == 1` 写分支。
3. **头指针不会因首结点变动而失效**。在不带头结点的版本里，删掉首结点必须修改调用者的 `head`，参数得传 `LinkList &`（指针的引用）；带头结点时传 `LinkList` 就够。

> **要点** 这是本章最容易在卷面上丢分的地方。**答题时先声明约定**："本链表带头结点。" 一句话能省掉后面所有的边界讨论。课件默认的是**不带头结点**（说 `head = nullptr` 表示空表），教材默认**带头结点**——遇到具体题目先看它给的图里首结点前面有没有那个空结点。

```cpp
// 带头结点的初始化
bool InitList(LinkList &L) {
    L = new LNode;              // 头结点
    if (L == nullptr) return false;
    L->next = nullptr;          // 空表
    return true;
}
```

### 3.2.2 不带头结点时的"首结点特例"

```cpp
// 在第 i 个位置插入，不带头结点的版本
bool ListInsert(LinkList &L, int i, int e) {
    if (i < 1) return false;
    if (i == 1) {                              // ← 只有这一个位置要改 L 本身
        LNode *s = new LNode{e, L};
        L = s;
        return true;
    }
    LNode *p = L;                              // 找到第 i-1 个
    for (int j = 1; j < i - 1 && p != nullptr; ++j) p = p->next;
    if (p == nullptr) return false;
    LNode *s = new LNode{e, p->next};
    p->next = s;
    return true;
}
```

若改成带头结点，`i == 1` 的那个分支可以直接删掉——因为第 $1$ 个位置的"前驱"就是头结点，进入通用流程即可。**这就是头结点存在的全部理由。**

## 3.3 单链表的基本操作

### 3.3.1 遍历

```cpp
void ListTraverse(LinkList L) {                // L 是头指针
    for (LNode *p = L->next; p != nullptr; p = p->next)  // 带头结点：从头结点的后继起
        std::cout << p->data << " ";
}
```

$O(n)$。循环终止条件是不带头结点 `p != nullptr`，带头结点也是 `p != nullptr`（跳到 `nullptr` 停）。

### 3.3.2 按位序取元素（$O(n)$）

```cpp
LNode *GetElem(LinkList L, int i) {
    if (i < 0) return nullptr;
    LNode *p = L;                              // 从头结点开始（i=0 返回头结点）
    for (int j = 0; p != nullptr && j < i; ++j) p = p->next;
    return p;
}
```

**这就是链表与顺序表最本质的差别**：没有地址算术，"第 $i$ 个"只能数。$i$ 越大越慢，平均走 $n/2$ 步，$O(n)$。

### 3.3.3 按值查找（$O(n)$）

```cpp
LNode *LocateElem(LinkList L, int e) {
    for (LNode *p = L->next; p != nullptr; p = p->next)
        if (p->data == e) return p;
    return nullptr;
}
```

返回的是**结点指针**而不是位序——链表里"位序"本身是个要数出来的东西，返回指针才有用（$O(1)$ 定位）。

### 3.3.4 插入（$O(1)$，已知前驱）

在结点 `p` **之后**插入 `s`：

```cpp
s->next = p->next;      // ① s 接过 p 原来的后继
p->next = s;            // ② p 改为指向 s
```

> **要点** **这两行的顺序不能换。** 若先执行 `p->next = s`，`p->next` 的旧值（原来那个后继）就丢了，第 ① 步再读 `p->next` 拿到的是 `s` 自己——结果是 `s->next = s`，一个自环，链表的剩余部分全部泄漏。这是"指针操作顺序"类改错题的原型，和顺序表"插入必须从后往前挪"是同一类错误的两个版本（都是**先保存再覆盖**）。

**在第 $i$ 个位置插入**：先找第 $i-1$ 个结点（$O(n)$），再执行上面两步（$O(1)$）。总代价 $O(n)$，但**慢在找，不在插**。

### 3.3.5 删除（$O(1)$，已知前驱）

删除 `p` 的后继 `q`：

```cpp
q = p->next;              // 记下要删的结点
p->next = q->next;        // 跨过它
delete q;                 // 释放（C/C++ 必须手动释放）
```

**漏掉 `delete` 就是内存泄漏**——这是与顺序表最大的实现差异：顺序表删除只是把 `length` 减一，空间还在表里；链表删除必须真的还给系统。

**补充：已知结点指针 `p`，删除 `p` 本身（$O(1)$）**

常规做法要先找 `p` 的前驱，$O(n)$。但若只要求"删除这个位置上的值"而不在乎物理结点是哪一个，可以**把后继的值抄到 `p` 里，然后删后继**：

```cpp
void DeleteNode(LNode *p) {                 // p 非尾结点
    LNode *q = p->next;
    p->data = q->data;                      // 金蝉脱壳：值前移
    p->next = q->next;
    delete q;
}
```

条件：**`p` 不是尾结点**。尾结点没有后继可抄，只能老实找前驱。这个技巧在单链表上很常用，代价是"结点的身份"和"元素的身份"被分开了——这也说明单链表的一个固有缺陷：**只能单向走，看得到后面看不到前面**。

### 3.3.6 建表：头插法与尾插法

**头插法**（每次插在头结点之后，得到**逆序**）：

```cpp
void CreateListHead(LinkList &L, const int a[], int n) {
    L = new LNode; L->next = nullptr;
    for (int i = 0; i < n; ++i) {
        LNode *s = new LNode{a[i], L->next};
        L->next = s;                        // 新结点总在最前
    }
}
```

输入 $1,2,3$，得到 $3,2,1$。$O(n)$，**可以用来就地逆置**。

**尾插法**（维护尾指针，得到**正序**）：

```cpp
void CreateListTail(LinkList &L, const int a[], int n) {
    L = new LNode; L->next = nullptr;
    LNode *r = L;                           // r 始终指向尾结点
    for (int i = 0; i < n; ++i) {
        LNode *s = new LNode{a[i], nullptr};
        r->next = s;
        r = s;                              // 尾指针后移
    }
}
```

输入 $1,2,3$，得到 $1,2,3$。若不用尾指针而每次走到表尾再接，建表就是 $O(n^2)$——这是"多维护一个指针换一个数量级"的经典例子。

### 3.3.7 求表长

```cpp
int ListLength(LinkList L) {
    int len = 0;
    for (LNode *p = L->next; p != nullptr; p = p->next) ++len;
    return len;
}
```

$O(n)$。**与顺序表的关键差别**：顺序表的 `length` 是**存在结构里的**，$O(1)$ 直读；链表要么走一遍（$O(n)$），要么额外维护一个长度字段（多占 $4$ 字节，且每次插删都要同步更新）。这也是"空间换时间"的一个小例子。

## 3.4 复杂度汇总

| 操作 | 方法 | 时间复杂度 |
|---|---|---|
| 遍历 | 从头扫到尾 | $O(n)$ |
| 按位序取第 $i$ 个 | 走 $i$ 步 | $O(n)$ |
| 按值查找 | 顺序扫描 | $O(n)$ |
| 在第 $i$ 位插入 | 找第 $i-1$ 个 + 改指针 | $O(n)$（**定位** $O(n)$，**插入本身** $O(1)$） |
| 删除第 $i$ 个 | 找第 $i-1$ 个 + 改指针 + 释放 | $O(n)$（**定位** $O(n)$，**删除本身** $O(1)$） |
| 表头插入 | 改两个指针 | $O(1)$ |
| 表头删除 | 改指针 + 释放 | $O(1)$ |
| 表尾插入 | 有尾指针则 $O(1)$，否则 $O(n)$ | 视实现 |
| 表尾删除 | 需找尾的**前驱**，单链表是 $O(n)$ | **注意这里是 $O(n)$** |

> **要点** 最后一行是常考陷阱：**单链表的表尾删除不是 $O(1)$**。要删尾结点必须改它前驱的 `next`，而单链表从尾结点找不到前驱，只能从头再走一遍。表尾插入可以靠尾指针做到 $O(1)$，表尾删除不行。双向链表或循环链表能解决这个（见 3.6）。

## 3.5 顺序表 vs 链表

| 方面 | 顺序表 | 链表 |
|---|---|---|
| 存储 | 连续（顺序存储） | 结点 + 指针（链式存储） |
| 按位访问 | $O(1)$ | $O(n)$ |
| 表头插删 | $O(n)$ | $O(1)$ |
| 表尾插 | $O(1)$ | $O(1)$（有尾指针）/ $O(n)$（无） |
| 表尾删 | $O(1)$ | $O(n)$（单链表）/ $O(1)$（双向） |
| 中间插删 | $O(n)$ | $O(n)$（**主要是定位代价**；已知前驱则 $O(1)$） |
| 空间 | 连续、紧凑，但有容量冗余（最多 $2$ 倍） | 离散、无冗余，但每结点多一个指针（存储密度约 $0.5$） |
| 容量 | 固定或需重分配 | 动态，随用随开 |
| 缓存局部性 | **好**（连续内存，预取命中） | **差**（随机跳转，每次可能缺页） |
| 随机访问、二分查找 | 支持 | **不支持** |

**选择原则**：

- **按索引读得多 → 顺序表**。链表做不了二分查找，这一条直接决定了有序查找只能建在顺组结构或用跳表/平衡树上。
- **频繁在表头/中间插删 → 链表**。注意这只在"已经定位到修改点"时成立；若每次都要先按位序找，链表的优势会被定位代价吃掉。
- **元素本身很大（拷贝贵）→ 链表**，因为链表搬的是指针。
- **内存紧张且规模可预测 → 顺序表**，链表每个结点都多一个指针。

> **补充** 实际工程里"链表比顺序表快"经常不成立，原因就是**缓存**：顺序表扫描 $100$ 万个 `int` 是 $4$ MB 连续内存，硬件预取几乎免费；同样多的链表结点散落在堆里，每次跳转都可能是一次 cache miss，实测能慢 $5$–$10$ 倍。所以 `std::vector` 在绝大多数场景下优于 `std::list`——**只有当插入删除真的频繁且已定位时，链表才赢**。这不是教材内容，但值得知道：**渐近复杂度相同的两个结构，常数因子可以差一个数量级**。

## 3.6 链表的变体

### 3.6.1 循环链表

尾结点的 `next` 不指向 `nullptr`，而是**指回头结点**（带头结点时）或**首结点**（不带头结点时），整个链成一个环。

**好处**：从任意结点出发都能走遍全表。适合"轮转"类问题（约瑟夫环、时间片轮转调度）。

**判空与遍历**：

| 写法 | 带头结点 | 不带头结点 |
|---|---|---|
| 判空 | `head->next == head` | `head == nullptr` |
| 遍历终止 | `p != head` | `p != head`（从 `head` 起走一圈） |
| 找尾结点 | 走到 `p->next == head` | 走到 `p->next == head` |

> **注意** 循环链表的 `while` 条件**绝不能写 `p != nullptr`**——永远不成立，死循环。这是改错题的常客。

**带尾指针的循环链表**有一个漂亮性质：`rear->next` 就是头结点，所以**表头插入、表尾插入都是 $O(1)$**；更进一步，**两个循环链表合并也是 $O(1)$**：

```cpp
// 把 B 接到 A 的尾部（均带尾指针 rearA, rearB，均带头结点）
LNode *hA = rearA->next;              // A 的头结点
rearA->next = rearB->next->next;      // A 尾接 B 的首结点
rearB->next = hA;                      // B 尾接 A 的头结点
```

这比单链表合并（要走完 A 找尾）快一个数量级。

### 3.6.2 双向链表

每个结点有 `prior` 和 `next` 两个指针。

```cpp
struct DNode {
    int    data;
    DNode *prior;      // 直接前驱
    DNode *next;       // 直接后继
};
```

**插入**：在 `p` 之后插入 `s`（四步，顺序有讲究）：

```cpp
s->prior = p;              // ① s 的前驱 = p
s->next  = p->next;        // ② s 的后继 = p 原来的后继
p->next->prior = s;        // ③ 原后继的前驱改为 s
p->next  = s;              // ④ p 的后继改为 s
```

**关键**：第 ③ 步必须用 `p->next` 的**旧值**，所以它必须在第 ④ 步之前。①②③ 三步都只读 `p->next` 或写 `s`/`p->next->prior`，互相不冲突，可以任意换序；**④ 是唯一会破坏旧值的操作，必须放最后**。

**边界**：第 ③ 步要求 `p->next != nullptr`，即这个写法只在 `p` **不是尾结点**时成立。若要在尾结点之后插入，须先判空并单独处理（或改用双向循环链表，此时尾结点的 `next` 指回头结点，不存在空指针）。

**删除**：删除 `p` 的后继 `q`：

```cpp
q = p->next;
p->next = q->next;         // ① 跨过 q
q->next->prior = p;        // ② 让新的后继指回 p
delete q;                  // ③ 释放
```

**与单链表对比**：

| | 单链表 | 双向链表 |
|---|---|---|
| 找前驱 | $O(n)$ | $O(1)$ |
| 表尾删除 | $O(n)$ | $O(1)$ |
| 空间 | 每结点 $1$ 个指针 | 每结点 $2$ 个指针 |
| 指针操作易错度 | 中 | **高**（四步，顺序敏感） |

实际最常用的形式是**双向循环链表**（Linux 内核的 `list_head` 就是），兼具"任意方向走"和"从任意结点走遍全表"。

### 3.6.3 静态链表（教材 2.6）

不用指针，用**数组**模拟链表：每个元素存 `data` 和 `next`（下一个元素的**数组下标**，`0` 或 `-1` 表示结束）。

| 下标 | data | next |
|---|---|---|
| 0 | A | 2 |
| 1 | C | 3 |
| 2 | B | 1 |
| 3 | E | 4 |
| 4 | D | -1 |

**读法**：从下标 $0$ 出发，`next` 的值就是下一个元素的**下标**。于是逻辑顺序为 A(0) → B(2) → C(1) → E(3) → D(4)。注意**下标顺序与逻辑顺序无关**——这正是"用下标代替地址"的含义。

**用途**：早期没有指针的语言（如 BASIC、FORTRAN）里实现链表；今天主要用于**在数组上做 $O(1)$ 插入删除**的题目（如并查集、某些图论实现）。插入时取一个空闲槽位（通常把空闲单元也串成一条"备用链表"）。

**代价**：容量固定，失去了链表"动态"的核心优势，只保留了"不搬移"的优势。

## 3.7 补充：两个有序链表的归并

对应 [[02-1-线性表·顺序表]] 2.9 节的顺序表版本，这里给出链表版，**对照看差异**。

**问题** 两个带头结点的单链表 `A`、`B` 元素非递减，归并成一个仍非递减的链表。

```cpp
void MergeList(LinkList &A, LinkList &B) {
    LNode *pa = A->next, *pb = B->next;
    LNode *pc = A;                          // 直接复用 A 的头结点作结果头
    while (pa != nullptr && pb != nullptr) {
        if (pa->data <= pb->data) { pc->next = pa; pc = pa; pa = pa->next; }
        else                      { pc->next = pb; pc = pb; pb = pb->next; }
    }
    pc->next = (pa != nullptr) ? pa : pb;    // 接上未走完的那一段
    delete B;                                // 释放 B 的头结点
    B = nullptr;                             // 调用者的 B 已失效，置空防误用
}
```

**关键差别**：

| | 顺序表归并 | 链表归并 |
|---|---|---|
| 时间 | $O(m+n)$ | $O(m+n)$ |
| 额外空间 | $O(m+n)$（必须开新表） | **$O(1)$**（只改指针，结点原地复用） |
| 实现难点 | 三指针 + 新表容量 | 尾插的指针维护 |

**为什么链表能做到 $O(1)$ 空间**？因为归并的本质是"重新排列已有元素"，而不是"复制元素"。链表重排只需改指针，结点自己待着不动；顺序表重排则必须真的搬元素，而两个有序段交叉排列，原地合并要么大量搬移要么另开空间。

> **要点** 这一个例子就把两种存储结构的取舍讲完了。**归并排序能用链表做到 $O(1)$ 额外空间递归深度外，用数组做不到**——这是后面排序章的一个伏笔。

## 订正

1. **课件通篇用"`head == nullptr` 表示空表"，即默认不带头结点**，而教材（严蔚敏 §2.5）和绝大多数考题默认**带头结点**。两种约定下"空表判据""首结点插删是否要特判""初始化代码"全都不同，**答题必须先声明**。本篇 3.2.1 把两套写法并列写出来了。
2. **第 4 页"`Empty list: head = nullptr (or NULL)`"在同页又把 head pointer 描述为"points to first node"**——这两句合起来只在不带头结点的版本里自洽。若采用带头结点，头指针指向的是**头结点**而不是首结点（首结点是 `head->next`）。这是本章最容易出概念错的一处。
3. **第 6 页复杂度表把"Insert at pos"标成 $O(n)$ 并在括号里注"实际插入 $O(1)$"**——表述是对的，但没点明关键：**$O(n)$ 来自定位（找前驱），不来自插入**。而"InsertFront/Back $O(1)$（if tail pointer known）"这一格把表头与表尾混在一起说：表头插入**不需要**尾指针就已是 $O(1)$，只有表尾插入才依赖尾指针。本篇 3.4 的表把它们拆开了。
4. **第 6 页漏了"表尾删除"这一行**，而单链表的表尾删除是 $O(n)$（找前驱），恰恰是最容易答错的一项。已补在 3.4。
5. **第 8 页"循环链表：last node's next points to head"** 表述含糊——严格说是**指回头结点**（带头结点时）或**指回首结点**（不带头结点时），不是"指回头指针"（指针不是结点，不能被指向）。判空条件也随之不同（3.6.1 的表）。
6. **第 3 页议程说"Circular & doubly lists (12 min)"，但正文只有一页两行**（第 8 页），连插入删除的指针操作都没写。双向链表的四步插入是考试重点，本篇 3.6.2 补全，并标了哪几步可以换序、哪一步不能。
7. **第 9 页说"Always free memory on delete/destroy to avoid leaks"**，但没有提醒相反方向的风险：`delete` 之后若继续访问原指针即悬垂指针（undefined behavior）。顺序表没有这个问题（空间还在表里），链表有，这个差异值得单独记。
