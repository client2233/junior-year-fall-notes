# 02-1 线性表·顺序表

> 系列：[[01-数据结构与算法概论]] · [[02-1-线性表·顺序表]] · [[02-2-线性表·链表]] · [[03-栈与队列]] · [[04-串]] · [[05-数组与特殊矩阵]]

同一个**逻辑结构**（线性表），两套**存储映射**：本篇讲顺序存储，下一篇讲链式存储。核心问题只有一个——**为什么 $\text{GetElem}$ 是 $O(1)$ 而 $\text{ListInsert}$ 是 $O(n)$？**

## 2.1 线性表的定义

**定义** 线性表是 $n\ (n \ge 0)$ 个**同类型**数据元素的**有限**序列

$$
L = (a_1, a_2, \dots, a_n).
$$

四个特点：

- **有序**：元素之间是有先后次序的，次序不能交换
- **有限**：$n$ 是有限值
- **同类型**：概念上属于同一数据类型（每个元素占同样大小的空间）
- **邻接关系**：除首尾外，每个元素有且仅有一个**直接前驱**和一个**直接后继**

**术语**：

| 术语 | 含义 |
|---|---|
| 表头元素 $a_1$ | 首元素，无前驱 |
| 表尾元素 $a_n$ | 尾元素，无后继 |
| 长度 | $n$ |
| 空表 | $n = 0$ |
| 位序 | $a_i$ 的位置是 $i$（**教材一律从 1 开始**） |

> **要点** **位序由次序定义，不由内存地址定义。** 这是整章的枢纽：正因为"位置"是逻辑概念，在中间插入一个元素会让它后面所有元素的位序整体 $+1$——顺序存储里就必须真的把它们都搬一格。链表之所以能 $O(1)$ 插入，是因为它压根没有"第几个"这个物理概念。

**例**：学生名单、数组、字符串、多项式的系数表。

> **补充** 多项式是教材的经典例子，值得单独记一下：$P_n(x)=p_0+p_1x+\cdots+p_nx^n$ 有两种存法——
>
> - **系数顺序表**：存 $(p_0,p_1,\dots,p_n)$，$x^i$ 的系数放在下标 $i$。适合稠密多项式，加法是逐项对齐相加，$O(n)$。
> - **稀疏表示**：每个非零项存（系数，指数）二元组，按指数有序排列。适合 $x^{1000}+1$ 这种稀疏情形。
>
> 这一对比说明：**"线性表"这个 ADT 不规定元素是什么**，元素本身可以是一个二元组。

## 2.2 逻辑结构与存储结构

**逻辑结构**：元素排成一条线，每个元素至多一个前驱、一个后继。

**两种经典存储映射**：

| 映射 | 逻辑相邻 | 物理相邻 | 位置怎么定位 |
|---|---|---|---|
| 顺序存储 | $a_i$ 的邻居是 $a_{i\pm1}$ | **是**（连续存放） | 地址算术 |
| 链式存储 | 同上 | **否**（可离散） | 指针跳转 |

一句话对比：

- 顺序存储：**逻辑邻居就是物理邻居** → 可以用地址算术，但插入必须挪。
- 链式存储：**逻辑邻居用指针连** → 不用挪，但不能算地址。

> **要点** ADT 不变，只换存储映射，操作的功能完全一样，**代价却换了一整张表**。这就是"数据结构"这门课真正的主题——不是学几种容器，而是学"同一个抽象在不同物理实现下的代价如何转移"。

## 2.3 线性表的 ADT

**数据对象**：$\{a_1,\dots,a_n\}$，$n \ge 0$，元素同类型。

**基本操作**（9 个，按教材编号）:

| 操作 | 功能 | 位序约束 |
|---|---|---|
| `InitList(&L)` | 初始化为空表 | —— |
| `DestroyList(&L)` | 销毁，释放空间 | —— |
| `ClearList(&L)` | 清空（保留结构） | —— |
| `ListEmpty(L)` | 判空 | —— |
| `ListLength(L)` | 求长度 | —— |
| `GetElem(L, i, &e)` | 取第 $i$ 个元素 | $1 \le i \le n$ |
| `LocateElem(L, e)` | 按值查找，返回位序或 $0$ | —— |
| `ListInsert(&L, i, e)` | 在第 $i$ 个位置**之前**插入 | $1 \le i \le n+1$ |
| `ListDelete(&L, i, &e)` | 删除第 $i$ 个元素，用 $e$ 返回 | $1 \le i \le n$ |
| `ListTraverse(L, visit)` | 依次对每个元素调用 `visit` | —— |

**ADT 隐含的契约**：

- 插入后，原来的 $a_i$ 变成 $a_{i+1}$（**相对次序不变**）
- 删除返回被删元素，并**合拢空隙**
- 位序始终从 $1$ 开始且**连续无空洞**

**参数约定**（教材符号，考试常考）：

- `&L` 表示**引用传递**，函数内可以修改表本身；不带 `&` 的（如 `L`）是值传递/只读。
- `&e` 表示**输出参数**，把结果带回给调用者。
- 返回值类型：`Status`（教材用 `OK`/`ERROR` 宏），C++ 里用 `bool` 等价。

## 2.4 ADT → C++ 接口

```cpp
struct SeqList;                                        // 存储结构见 2.5

void InitList(SeqList &L);                             // 初始化
void DestroyList(SeqList &L);                          // 销毁
bool ListEmpty(const SeqList &L);                      // 判空
int  ListLength(const SeqList &L);                     // 求长度
bool GetElem(const SeqList &L, int pos, int &e);       // 取第 pos 个
int  LocateElem(const SeqList &L, int e);              // 按值查找，返回位序或 0
bool ListInsert(SeqList &L, int pos, int e);           // 1 <= pos <= n+1
bool ListDelete(SeqList &L, int pos, int &e);          // 1 <= pos <= n
void ListTraverse(const SeqList &L);                   // 遍历
```

三个设计要点：

- `const SeqList &`：只读视图，**不拷贝**整个表（若按值传参，一次调用就 $O(n)$）。
- `bool` 返回值：成功/失败，替代教材的 `Status`。
- `int &e`：输出参数。

## 2.5 顺序存储与地址计算

**定义** 用一组**地址连续**的存储单元依次存放线性表的元素，称为**顺序表**。

逻辑次序与物理次序完全一致：

```
逻辑:   a1      a2      a3    ...   an
内存:  [a1]    [a2]    [a3]   ...  [an]     连续
下标:   0       1       2     ...  n-1      C++（从 0）
位序:   1       2       3     ...   n        教材（从 1）
```

**地址计算公式**（设每个元素占 $c$ 个字节，$a_1$ 的地址为 $\mathrm{Loc}(a_1)$）：

$$
\mathrm{Loc}(a_i) = \mathrm{Loc}(a_1) + (i-1)\times c .
$$

一次乘法加一次加法，与 $n$ 无关，因此**随机存取**（random access）$O(1)$。这是顺序表唯一不可替代的优势。

### 2.5.1 C++ 表示

```cpp
const int MAX_SIZE = 100;      // 静态容量

struct SeqList {
    int data[MAX_SIZE];        // 顺序存储
    int length;                // 当前元素个数 n
};

void InitList(SeqList &L) { L.length = 0; }        // O(1)
int  ListLength(const SeqList &L) { return L.length; }
```

两条硬规矩：

- `data[i]` 存的是 $a_{i+1}$（**下标 = 位序 - 1**）。
- **`length` 不是 `capacity`**。`data[0..length-1]` 有效，`length` 之后的槽是垃圾数据，不许读。

## 2.6 基本操作的实现

### 2.6.1 取元素 GetElem（$O(1)$）

```cpp
bool GetElem(const SeqList &L, int pos, int &value) {
    if (pos < 1 || pos > L.length) return false;   // 越界检查
    value = L.data[pos - 1];                        // 一次访存
    return true;
}
```

**例** `int a[5] = {7, 11, 13, 17, 19}`，4 字节 `int`：

| 位序 | 下标 | 地址偏移 | 值 |
|---|---|---|---|
| 1 | 0 | base + 0 | 7 |
| 2 | 1 | base + 4 | 11 |
| 3 | 2 | base + 8 | 13 |

一次边界检查 + 一次访存 = $O(1)$，**与 $n$ 无关**。

### 2.6.2 按值查找 LocateElem（$O(n)$）

顺序表一般**不是有序的**，所以只能**顺序查找**：

```cpp
int LocateElem(const SeqList &L, int value) {
    for (int i = 1; i <= L.length; ++i) {
        if (L.data[i - 1] == value) return i;      // 成功，返回位序
    }
    return 0;                                       // 失败
}
```

| 情况 | 比较次数 |
|---|---|
| 最好（第 1 个命中） | $1$ |
| 最坏（末位命中或不存在） | $n$ |
| 平均（等概率） | $(n+1)/2$ |

> **补充** 平均情况要分两种口径，教材只算了"成功"那种。**查找成功**、每个位置等概率 $1/n$ 时，比较次数等于被查元素的位置 $i$，故

$$
\frac{1}{n}\sum_{i=1}^{n} i = \frac{n+1}{2}.
$$

> **查找失败**：固定 $n$ 次。若再按"成功概率 $p$、失败概率 $1-p$"加权，期望是 $p\cdot\dfrac{n+1}{2}+(1-p)n$。

**折半查找要求表有序**，那是第 11 章的内容，不能套在无序顺序表上。

### 2.6.3 插入 ListInsert（$O(n)$）

```cpp
bool ListInsert(SeqList &L, int pos, int value) {
    if (pos < 1 || pos > L.length + 1) return false;   // 位序非法
    if (L.length >= MAX_SIZE)          return false;   // 上溢
    for (int i = L.length; i >= pos; --i) {            // 从后往前挪
        L.data[i] = L.data[i - 1];
    }
    L.data[pos - 1] = value;
    ++L.length;
    return true;
}
```

**逐步跟踪**：向 $[10,20,30]$ 的第 2 个位置插入 $15$，容量 $\ge 4$。

| 步 | 执行的代码 | `data[0..3]` | `length` |
|---|---|---|---|
| 0 | 初始 | `[10, 20, 30, _]` | 3 |
| 1 | `i=3`: `data[3]=data[2]` | `[10, 20, 30, 30]` | 3 |
| 2 | `i=2`: `data[2]=data[1]` | `[10, 20, 20, 30]` | 3 |
| 3 | `data[1]=15` | `[10, 15, 20, 30]` | 3 |
| 4 | `++length` | `[10, 15, 20, 30]` | 4 |

> **为什么必须从后往前？** 若从前往后（`data[2]=data[1]` 先做），`20` 会被 `10` 覆掉，`30` 那一步再抄就抄到错的值。**尾部先行，保证每个源值在被覆盖前已经复制走。** 这是顺序表插入唯一的易错点，也是每年必考的"改错题"。

**移动次数**：插在第 $i$ 个位置，要挪 $a_i,\dots,a_n$，共 $n-i+1$ 个。

- 最好：$i = n+1$（末尾追加），移动 $0$ 次，$O(1)$
- 最坏：$i = 1$（表头插入），移动 $n$ 次，$O(n)$

### 2.6.4 删除 ListDelete（$O(n)$）

```cpp
bool ListDelete(SeqList &L, int pos, int &value) {
    if (pos < 1 || pos > L.length) return false;
    value = L.data[pos - 1];                            // 先保存被删值
    for (int i = pos; i < L.length; ++i) {              // 从前往后挪
        L.data[i - 1] = L.data[i];
    }
    --L.length;
    return true;
}
```

**逐步跟踪**：从 $[10,15,20,30]$ 删第 2 个。

| 步 | 执行的代码 | `data[0..3]` | `length` |
|---|---|---|---|
| 0 | 初始 | `[10, 15, 20, 30]` | 4 |
| 1 | `value = data[1]` → $15$ | `[10, 15, 20, 30]` | 4 |
| 2 | `i=2`: `data[1]=data[2]` | `[10, 20, 20, 30]` | 4 |
| 3 | `i=3`: `data[2]=data[3]` | `[10, 20, 30, 30]` | 4 |
| 4 | `--length` | `[10, 20, 30, _]` | 3 |

**注意**：数组里物理上仍留着那个过期的 `30`，这**不要紧**——**`length` 才是逻辑表的唯一真相**。但反过来，`length` 之后的位置绝不能读，读出来是垃圾。

**为什么从前往后？** 删除是左移，若先抄 `data[3]` 到 `data[2]`，`data[2]` 的原值就被毁了。

**移动次数**：删第 $i$ 个，要挪 $a_{i+1},\dots,a_n$，共 $n-i$ 个。

- 最好：$i = n$（删表尾），$0$ 次，$O(1)$
- 最坏：$i = 1$（删表头），$n-1$ 次，$O(n)$

### 2.6.5 常见错误对照

| 错误 | 正确做法 |
|---|---|
| 插入时从左往右挪 | `for (i = length; i >= pos; --i)` |
| 删除时从右往左挪 | `for (i = pos; i < length; ++i)` |
| 位序范围写错 | 插入 $1..n+1$；删除/取元素 $1..n$ |
| 漏掉上溢检查 | `length >= MAX_SIZE` 时拒绝 |
| 位序与下标混用 | 只在访问 `data[...]` 时做 $-1$ |
| 读 `data[length]` | 该槽是垃圾 |

## 2.7 平均移动次数

教材的两个公式，考试几乎必考，**要会自己推**。

### 2.7.1 插入

在第 $i$ 个位置插入（$1 \le i \le n+1$），移动 $n-i+1$ 个元素。设 $n+1$ 个位置**等概率**，则

$$
\bar{M}_{\text{insert}} = \frac{1}{n+1}\sum_{i=1}^{n+1}(n-i+1) = \frac{1}{n+1}\sum_{k=0}^{n}k = \frac{1}{n+1}\cdot\frac{n(n+1)}{2} = \frac{n}{2}.
$$

### 2.7.2 删除

删第 $i$ 个（$1 \le i \le n$），移动 $n-i$ 个。设 $n$ 个位置等概率：

$$
\bar{M}_{\text{delete}} = \frac{1}{n}\sum_{i=1}^{n}(n-i) = \frac{1}{n}\cdot\frac{(n-1)n}{2} = \frac{n-1}{2}.
$$

两者都是 $\Theta(n)$，因此**平均也是 $O(n)$**；表尾操作是唯一 $O(1)$ 的例外。

> **要点** 平均与最坏同阶这件事很重要：**不能说"平均情况快，所以顺序表插入还行"**。$n/2$ 次移动在大表上就是真的慢。`memmove` 只能把常数因子压下去，改不了阶。

> **补充（概率假设的敏感性）** 上面的推导用了"等概率"。若插入位置不是均匀分布（例如 90% 的插入都在表尾），平均值会显著变小——极端情形下全是表尾追加，平均就是 $O(1)$。所以答"平均 $n/2$"时应当写明假设，这是教材的隐含前提。考试照抄 $n/2$、$(n-1)/2$ 即可。

## 2.8 复杂度汇总

| 操作 | 最好 | 平均 | 最坏 |
|---|---|---|---|
| `GetElem(L, pos, &e)` | $O(1)$ | $O(1)$ | $O(1)$ |
| `LocateElem(L, e)` | $O(1)$ | $O(n)$ | $O(n)$ |
| `ListInsert(&L, pos, e)` | $O(1)$（表尾） | $O(n)$ | $O(n)$（表头） |
| `ListDelete(&L, pos, &e)` | $O(1)$（表尾） | $O(n)$ | $O(n)$（表头） |
| `ListLength` / `ListEmpty` | $O(1)$ | $O(1)$ | $O(1)$ |
| `ListTraverse` | $O(n)$ | $O(n)$ | $O(n)$ |

**关键**：插入删除的代价是**移动元素的个数**，不是那一次赋值。

## 2.9 补充：两个有序顺序表的归并

教材这一节的经典例题，课件里没有，但**考试必考、且是后面归并排序的基础**。

**问题** 已知顺序表 `LA`、`LB` 的元素**非递减有序**，把它们归并到 `LC`，仍非递减有序。

**算法**：双指针。`i` 指 `LA`、`j` 指 `LB`、`k` 指 `LC`，每次取两者较小者放入 `LC`，然后指针后移；某个表走完后把另一个表的剩余部分整段抄过去。

```cpp
void MergeList(const SeqList &LA, const SeqList &LB, SeqList &LC) {
    int i = 0, j = 0, k = 0;                      // 三表均用 0 基下标
    while (i < LA.length && j < LB.length) {
        if (LA.data[i] <= LB.data[j]) LC.data[k++] = LA.data[i++];
        else                          LC.data[k++] = LB.data[j++];
    }
    while (i < LA.length) LC.data[k++] = LA.data[i++];   // 抄完 LA 剩余
    while (j < LB.length) LC.data[k++] = LB.data[j++];   // 抄完 LB 剩余
    LC.length = k;
}
```

**代价**：

- 时间 $O(m+n)$：三个 `while` 加起来恰好执行 $m+n$ 次，每个元素只被抄一次。
- 空间 $O(m+n)$：`LC` 是新开的表。**这是顺序存储的固有代价**——归并结果无法原地存放，因为两个有序段交叉，原地合并需要大量搬移（下一篇会看到，链表做同样的事只要 $O(1)$ 额外空间，改指针即可）。

> **要点** 这是"**顺序 vs 链式**"第一次在具体算法上分出高下，值得记住这个对照：归并在顺序表上 $O(m+n)$ 时间 + $O(m+n)$ 空间；在链表上 $O(m+n)$ 时间 + **$O(1)$ 空间**。后面学归并排序时，这个差别会直接决定能不能做"链表排序"。

## 2.10 补充：就地逆置

**问题** 把顺序表就地逆置，要求 $S(n)=O(1)$。

```cpp
void ReverseList(SeqList &L) {
    for (int i = 0, j = L.length - 1; i < j; ++i, --j) {
        int t = L.data[i]; L.data[i] = L.data[j]; L.data[j] = t;
    }
}
```

交换 $\lfloor n/2 \rfloor$ 次，时间 $O(n)$，空间 $O(1)$——这就是 1.6.1 说的**原地工作**。若用"另开一个数组倒着抄"的写法，空间是 $O(n)$，属于没答到点子上。

## 2.11 动态数组

### 2.11.1 静态结构的困境

`MAX_SIZE` 是编译期常量：

```cpp
SeqList L; InitList(L);
for (int i = 0; i < 100; ++i) ListInsert(L, i + 1, i);
ListInsert(L, 101, 42);        // 失败：上溢
```

开小了会**假性上溢**，开大了浪费内存，而真实负载根本不知道 $n$ 是多少。

**动态数组**的思路：在**堆**上维护一块缓冲区，另存 `length` 与 `capacity`；扩容时新开更大的块、拷贝、释放旧的。

- **扩容**：`length == capacity` 时**倍增**
- **缩容**：装载因子降到 $1/4$ 时**减半**

### 2.11.2 骨架

```cpp
class DynList {
  public:
    DynList() : data_(nullptr), length_(0), capacity_(0) {}
    ~DynList() { delete[] data_; }
    int length()   const { return length_; }
    int capacity() const { return capacity_; }
    int at(int pos) const { return data_[pos - 1]; }    // O(1)
    void push_back(int v);                              // 尾插，均摊 O(1)
    bool pop_back(int &v);                              // 尾删，均摊 O(1)
    bool insert(int pos, int v);                        // O(n) 搬移
    bool erase(int pos, int &v);                        // O(n) 搬移
  private:
    void realloc_to(int new_cap);                       // 分配 + 拷贝 + 释放
    int *data_; int length_; int capacity_;
};
```

### 2.11.3 重分配

```cpp
void DynList::realloc_to(int new_cap) {          // 要求 new_cap >= length_
    if (new_cap == capacity_) return;
    int *fresh = new int[new_cap];               // 1) 分配
    for (int i = 0; i < length_; ++i) {
        fresh[i] = data_[i];                     // 2) 拷贝 n 个，O(n)
    }
    delete[] data_;                              // 3) 释放旧块
    data_ = fresh;                               // 4) 接管
    capacity_ = new_cap;
}
```

**正确性的关键**：先分配、再拷贝、**最后**才 `delete[]`。顺序颠倒就是悬垂指针。

### 2.11.4 为什么是倍增而不是 $+1$

```cpp
void DynList::push_back(int value) {
    if (length_ == capacity_) {                  // 满了就翻倍
        realloc_to(capacity_ == 0 ? 1 : 2 * capacity_);
    }
    data_[length_++] = value;                    // 不扩容时 O(1)
}
```

- **每次只加一个槽**：每次追加都要拷贝 $n$ 个元素，单次 $O(n)$，$n$ 次共 $O(n^2)$。
- **倍增**：容量序列 $1,2,4,8,\dots$，总共只扩容 $\log_2 n$ 次。昂贵的拷贝被摊到大量廉价追加上 → **均摊 $O(1)$**。

### 2.11.5 扩容跟踪

| 追加序号 | length | capacity | 本次拷贝 | 累计拷贝 |
|---|---|---|---|---|
| 1 | 1 | 1 | 0 | 0 |
| 2 | 2 | 2 | 1 | 1 |
| 3 | 3 | 4 | 2 | 3 |
| 4 | 4 | 4 | 0 | 3 |
| 5 | 5 | 8 | 4 | 7 |
| 6–8 | 6–8 | 8 | 0 | 7 |
| 9 | 9 | 16 | 8 | 15 |

扩容只发生在 $n$ 是 $2$ 的幂时。9 次追加总共拷贝 $1+2+4+8=15 < 2n$。

### 2.11.6 均摊分析（聚合方法）

设第 $i$ 次 `push_back` 的实际代价为 $c_i$（$1$ 次写入，扩容时再加拷贝）：

$$
T(n) = \sum_{i=1}^{n} c_i \le n + \sum_{j=0}^{\lfloor \log_2 n \rfloor} 2^j \le n + 2n = 3n = O(n).
$$

于是单次均摊代价

$$
\frac{T(n)}{n} \le 3 = O(1).
$$

**几何级数的关键**：每次扩容拷贝的量是上一次的两倍，所以**最后一项主导整个和**。所有拷贝加起来仍是 $O(n)$，与"写入"本身同阶。

### 2.11.7 均摊分析（势能方法）

聚合法的缺点是"只对 $n$ 次连续追加有效"。势能法给出更强的结论：**对任意操作序列**都成立。

取势函数

$$
\Phi = 2\,\text{length} - \text{capacity},
$$

每次 `push_back` 记 3 个信用点：$1$ 个付写入，$2$ 个存为势能。

- **普通追加**：实际代价 $1$，$\Delta\Phi = +2$，均摊代价 $1+2 = 3$。
- **触发扩容的追加**（设扩容前 `length = capacity = c`）：实际代价 $c+1$（拷贝 $c$ 个 + 写入 $1$ 个）；扩容后 `length = c+1`、`capacity = 2c`，故 $\Phi_{\text{before}} = 2c-c = c$，$\Phi_{\text{after}} = 2(c+1)-2c = 2$，$\Delta\Phi = 2-c$。均摊代价 $(c+1)+(2-c) = 3$。

两种情形都是 $3$，所以从空表开始的任意 $n$ 次追加总代价 $\le 3n$。

> **要点** **均摊 $O(1)$ 是"对序列的最坏保证"，不是概率意义上的平均。** 平均情况需要输入的分布假设，均摊不需要——它是确定性的。单次操作仍然可能花 $O(n)$，但不可能连续多次都这样。

### 2.11.8 缩容与"抖动"

```cpp
bool DynList::pop_back(int &value) {
    if (length_ == 0) return false;
    value = data_[--length_];
    if (capacity_ > 1 && length_ <= capacity_ / 4) {   // 装载因子 <= 1/4
        realloc_to(capacity_ / 2);
    }
    return true;
}
```

**为什么缩容阈值是 $1/4$ 而不是 $1/2$？**

| 缩容阈值 | 在边界上交替 push/pop | 结果 |
|---|---|---|
| $n \le \text{cap}/2$ | 扩容后立刻又满足缩容条件 | 每次操作都 $O(n)$，**抖动（thrashing）** |
| $n \le \text{cap}/4$ | 缩容后仍有 $\text{cap}/4$ 个空位 | 边界附近不会触发重分配 |

定量地看：在 $1/4$ 阈值下减半后，容量至少是 $2n$，要再触发一次重分配必须先做 $\Theta(n)$ 次廉价操作，均摊 $O(1)$ 才守得住。

**教训：扩容与缩容的阈值必须分开（滞回，hysteresis），绝不能用同一个阈值。**

### 2.11.9 动态数组复杂度总结

| 操作 | 单次最坏 | 均摊 | 原因 |
|---|---|---|---|
| `push_back`（尾插） | $O(n)$（扩容时） | $O(1)$ | 倍增 |
| `pop_back`（尾删） | $O(n)$（缩容时） | $O(1)$ | $1/4$ 阈值 |
| `at` / `GetElem` | $O(1)$ | $O(1)$ | 地址算术 |
| 中间 insert / erase | $O(n)$ | $O(n)$ | 搬移主导 |

内存开销：增长后最多 $2$ 倍，缩容前最多 $4$ 倍冗余。

> **要点** **均摊不解决中间插入的慢**。搬移是顺序存储的固有属性，与扩容策略无关。要把中间插入降到 $O(1)$，只能换存储结构——这就是下一篇的链表。

### 2.11.10 三种复杂度别混

| 度量 | 回答的问题 | 本例 |
|---|---|---|
| 单次最坏 | 一次操作最坏多贵 | 扩容时的 `push_back`：$O(n)$ |
| 平均情况 | 随机输入下的期望 | `LocateElem`：$(n+1)/2$ 次比较 |
| 均摊 | 最坏操作序列的总代价 / 操作数 | $n$ 次 `push_back`：每次 $O(1)$ |

## 2.12 何时用顺序表

**适合**：

- 按位置访问频繁（`GetElem` / `at`）
- 很少在中间或表头插删
- 主要在表尾追加——动态数组给均摊 $O(1)$
- 内存充裕、看重缓存局部性（连续内存的扫描命中率远高于链表）

**不适合**：

- 任意位置频繁插删（尤其表头）
- 规模大且不可预测（最多浪费一倍容量）
- 元素本身拷贝代价高（搬移时反复拷贝）

**工作量对照**：

| 负载 | 顺序表 | 说明 |
|---|---|---|
| 访问 `a[i]` | $O(1)$ | 地址算术，无可替代 |
| 表尾追加 | $O(1)$ 静态 / $O(1)$ 均摊动态 | 重分配很少发生 |
| 表头插删 | $O(n)$ | 每个元素都要动 |
| 中间插删 | $O(n)$ | 平均一半元素要动 |
| 内存 | 紧凑，但有容量冗余 | 无每结点指针开销 |

**一句话**：**按索引读得多就用顺序表，改得多就用链表。**

## 订正

1. **第 13 页的 `InitList` 注释说"`data[]` 保持未初始化"**——作为说明没问题，但若后续代码依赖未初始化内存就是未定义行为。规范做法是在 `InitList` 里不清 `data`，但**所有读取必须受 `length` 保护**，课件没有把这条约束写死。
2. **第 19 页"插入代价 $n-\text{pos}+1=2$"的算式用得是位序**，而第 20 页的跟踪表用 0 基下标（`i=3: data[3]=data[2]`）。两套编号在同一节里混用，容易在考试时把 `n-i+1` 和 `n-i` 写反。**统一口径**：按**位序**记公式（插入 $n-i+1$、删除 $n-i$），按**下标**写代码。
3. **第 31 页"`new int[0]` 合法但无意义"**——严格说 `new int[0]` 的行为是合法的：它返回一个**可被 `delete[]`** 的指针（可能为空，也可能非空，标准不保证），不能解引用。所以这一句不算错，只是措辞上"无意义"应改成"合法但必须与容量为 $0$ 的特殊处理配套，且任何访问都越界"。
4. **第 34 页势能分析里 $\Delta\Phi = 2-n$ 的 $n$ 指扩容前的 `length`**（$= \text{capacity}$），与全文用 $n$ 表示"元素个数"的约定撞了符号。读的时候注意这个 $n$ 是当时的长度，不是最终的 $n$；本篇 2.11.7 改用 $c$。
5. **第 17 页表里 `ListTraverse` 的"最好/平均/最坏"全填 $O(n)$** 是对的，但遍历 $0$ 个元素的空表实际是 $O(1)$。这种边角不必进表，知道即可。
