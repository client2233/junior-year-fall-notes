# 04 串

> 系列：[[01-数据结构与算法概论]] · [[02-1-线性表·顺序表]] · [[02-2-线性表·链表]] · [[03-栈与队列]] · [[04-串]] · [[05-数组与特殊矩阵]]

串是元素为字符的线性表，但它多出一整套**整串语义**的操作：按字典序比较、连接、取子串、定位。这些都不是"按下标存取"能表达的，所以串必须有自己的 ADT。这一讲的重头是**模式匹配**：朴素算法为什么浪费，KMP 靠什么把 $O(nm)$ 压到 $O(n+m)$。

## 5.1 串的概念与术语

**定义 5.1.1（串）** 串是由零个或多个字符组成的有限序列

$$
S=c_1c_2\cdots c_n,\qquad n\ge 0.
$$

$n$ 为串的**长度**，记作 $|S|$。$n=0$ 时为空串，记作 `""`。

**空格串**只由空格组成，长度大于零，与空串**不是**一回事：`" "` 的长度是 $1$，`""` 的长度是 $0$。

| 术语 | 含义 | 例（以 `database` 为主串） |
|---|---|---|
| 子串 | 串中连续的一段 | `data` |
| 主串 | 被查找的那个串 | `database` |
| 前缀 | 从第 1 个字符开始的子串 | `data` |
| 后缀 | 以最后一个字符结尾的子串 | `base` |
| 真前缀 / 真后缀 | 不等于整串的前缀（后缀） | `dat` / `ase` |

约定：**子串必须连续**。`dtt` 不是 `database` 的子串（它是子序列），这是串与一般线性表在"取子集"上最容易混的一处。

> **补充（位置口径）** 教材公式用 1 基位置，C++ 代码用 0 基，写式子时必须声明用的是哪一套。本课程课件统一 0 基：`Index` 返回 0 基起始下标，未找到返回 `-1`。教材的 `Index` 返回 1 基位置，未找到返回 `0`。**这两套的"未找到"取值不同，混用就是把 $-1$ 当合法位置用**。

## 5.2 串的 ADT 与操作约定

| 操作 | 约定 |
|---|---|
| `StrAssign(S, chars)` | 用字符序列赋值 |
| `StrCopy(T, S)` | 深复制，不共享缓冲区 |
| `StrEmpty` / `StrLength` | 判空；长度按字符数计 |
| `StrCompare(S, T)` | 按字典序返回 $-1/0/1$ |
| `Concat(T, S1, S2)` | 连接，需检查目标容量 |
| `SubStr(Sub, S, pos, len)` | 取连续子串，需检查边界 |
| `Index(S, T)` | 返回 $T$ 在 $S$ 中首次出现的位置或 $-1$ |

**接口约定（考试爱考）**：

- 比较必须按**无符号字符**进行，否则高位字节（$\ge 128$）的顺序会反过来；
- 凡是**写入**的操作都要接收目标容量 `cap`（含末尾的 `'\0'`），返回新长度或 $-1$；
- 凡是**读取**的操作都要先验指针，空指针不是合法串；
- 缓冲区归调用方所有，ADT 不背着调用方分配内存。

## 5.3 三种存储表示

| 表示 | 做法 | 特点 |
|---|---|---|
| 定长顺序 | 定长字符数组加长度字段 | 简单、缓存友好、下标 $O(1)$；容量固定，长串被截断 |
| 堆分配 | 堆上缓冲区，记录长度与容量 | 按需增长，追加均摊 $O(1)$；需自行管理所有权 |
| 块链 | 每个结点存一小块字符 | 不必为每个字符配一个指针；块内插删需分裂合并，随机访问差 |

定长顺序存储的教材写法常用 `ch[0]` 存长度、字符从 `ch[1]` 起，与 C 风格"字符从 0 起、末尾放 `'\0'`"不同。两种约定混用是差一错误的根源。

**块链的意义**：长文本用单链表存会为每个字符搭一个指针（32 位机上单字符结点是 $1$ 字节数据 + $4$ 字节指针，利用率约 $1/5$；64 位机上是 $1/9$），分块后一个指针服务一整块，利用率随块长增大而趋近 $1$。

> **补充（三种表示的取舍本质）** 定长是"用固定上界换常数最小"，堆分配是"用一次重分配换增长能力"，块链是"用块内搬移换指针开销"。三者都没有改变"串是字符的有限序列"这一抽象，改变的只是**在哪个维度上付代价**——这正是 [[01-数据结构与算法概论]] 里"逻辑结构相同、存储结构不同、运算实现不同"的第三个实例（前两个是顺序表/链表、顺序栈/链栈）。

## 5.4 两种字符串约定

| 方面 | C 风格串（`'\0'` 结尾） | 长度前缀串 |
|---|---|---|
| 结束标记 | 空字符 `'\0'` | 显式长度字段 |
| 求长代价 | $O(n)$ 扫描 | $O(1)$ 直读 |
| 串内空字符 | 不可能表示 | 可以表示 |
| 越界风险 | 高（不检查容量时） | 较低 |
| 兼容性 | C/C++ 标准库 | 自定义结构 |

长度前缀的最大好处不只是 $O(1)$ 求长：它允许串内部出现 `'\0'`，于是"二进制安全的字符串"成为可能。反过来，C 风格串能直接交给任何库函数，兼容性无可替代——`std::string` 选择"长度 + `'\0'` 双保险"，正是两个都要。

## 5.5 基本操作的代价

| 操作 | 代价 | 要点 |
|---|---|---|
| 求长度 | $O(n)$ | C 风格串无长度字段，须扫到 `'\0'`；长度前缀串为 $O(1)$ |
| 比较 | $O(\min(|S|,|T|))$ | 首个不同字符决定大小；一方是另一方的前缀时，短者更小 |
| 复制 | $O(|S|)$ | 目标需 $|S|+1$ 字节；自复制（源与目标重叠）行为未定义 |
| 连接 | $O(|S_1|+|S_2|)$ | 先检查容量再写；失败时目标保持不变 |
| 求子串 | $O(\text{len})$ | 越界时截断到末尾，只有位置非法或容量不足才失败 |

这些操作都不难，代价却很不对称：定长表示下连接可能整体失败，堆分配表示下连接要重新分配并复制。**"同一 ADT、不同存储表示"** 在这里体现得最直接。

## 5.6 模式匹配问题

给定主串 $T$（长度 $n$）与模式串 $P$（长度 $m$），求

$$
\mathrm{Index}(T,P)=\min\{\,i \mid T[i..i+m-1]=P[0..m-1]\,\},
$$

即首次出现的起始位置，不存在时返回 $-1$。$m>n$ 时必不匹配；$m=0$ 时约定答案为 $0$。

## 5.7 朴素匹配

对每个起点 $i=0,1,\dots,n-m$，从 $P$ 的首字符开始逐个比较，失配则 $i$ 后移一位、$j$ 归零。

```cpp
int naiveMatch(const std::string &T, const std::string &P) {
    int n = T.size(), m = P.size();
    if (m == 0) return 0;
    for (int i = 0; i + m <= n; ++i) {
        int j = 0;
        while (j < m && T[i + j] == P[j]) ++j;
        if (j == m) return i;
    }
    return -1;
}
```

**逐起点核算**：以 $T=$ `ababcabcacbab`（$n=13$）、$P=$ `abcac`（$m=5$）为例。下表中 ✓ 表示该位相等、× 表示失配；× 前后两个字符分别是 $T$ 与 $P$ 在该位的字符。

| 起点 $i$ | 比较过程 | 次数 | 结果 |
|---|---|---|---|
| 0 | `a`✓ `b`✓ `a`×`c` | 3 | 失败 |
| 1 | `b`×`a` | 1 | 失败 |
| 2 | `a`✓`b`✓`c`✓`a`✓`b`×`c` | 5 | 失败 |
| 3 | `b`×`a` | 1 | 失败 |
| 4 | `c`×`a` | 1 | 失败 |
| 5 | `a`✓`b`✓`c`✓`a`✓`c`✓ | 5 | **命中** |

合计 $3+1+5+1+1+5=16$ 次，匹配位置 $i=5$。

> **要点** 计数时**失配的那一次也算一次比较**。$i=0$ 处是"两次命中 + 一次失配"，共 3 次；把失配那次漏掉就会得到 $2+1+5+1+1+5=15$，与真实值差一。这个坑极常见（连课件都踩了，见订正 1）。

**最坏情况**：$T$ 为 $n$ 个 `a`、$P$ 为 $m-1$ 个 `a` 加一个 `b`。每个起点都要比到最后一位才失败，故总比较次数为 $(n-m+1)m$ 次，即 $O(nm)$；当 $m\approx n/2$ 时达到 $\Theta(n^2)$。空间 $O(1)$。

**最好情况**：每个起点的首字符就失配，$O(n)$。

> **补充（朴素算法并不总是慢）** 在随机文本上，每次尝试的期望比较次数是 $O(1)$（首字符失配概率 $1-1/|\Sigma|$），故期望时间 $O(n)$。朴素算法的真正问题在**最坏情况**：文本与模式高度重复（DNA、二进制串、长串 `aaaa…`）时退化为 $\Theta(nm)$。KMP 的价值是**给出最坏情况的保证**，不是"平均更快"。

## 5.8 KMP 的核心思想

失配时，主串中已匹配的那段 $T[i-j..i-1]$ 是**已知的**，它等于 $P[0..j-1]$。它的某个**后缀**可能恰好等于模式串的某个**前缀**，这段重叠部分不必重新比较，直接把模式串右移即可。

于是：**主串指针 $i$ 永不回退**，只让模式指针 $j$ 按 next 数组回退，总代价降到 $O(n+m)$。

**正确性（为什么右移这么多是安全的）** 设当前在 $T[i]$ 处失配，已匹配 $j$ 个字符，即 $T[i-j..i-1]=P[0..j-1]$。若把模式串右移 $s$ 位（$0<s<j$）后能匹配，则必须有

$$
P[0..j-s-1]=P[s..j-1],
$$

也就是说 $P[s..j-1]$ 是 $P[0..j-1]$ 的一个**真前缀且同时是真后缀**，长度 $j-s$。反过来，任何长度为 $\ell$ 的这样的 border 都对应一个可行位移 $s=j-\ell$。取**最长**的 border（长度 $\mathrm{next}[j-1]$），得到**最小**的可行位移 $s=j-\mathrm{next}[j-1]$；比它更小的位移（$s<j-\mathrm{next}[j-1]$）全部不可能匹配。所以把 $j$ 直接置为 $\mathrm{next}[j-1]$ 不丢任何解。$\square$

> **要点** KMP 没有"跳过"任何信息，它跳过的是**已经被 border 结构证明不可能的位置**。$P[0..j-1]$ 里哪些前缀同时是后缀，这个信息只依赖模式串本身，可以预处理一次、供任意多个文本复用——这是它能做到 $O(n+m)$ 的根本原因。

## 5.9 next 数组（0 基前缀函数）

### 5.9.1 定义

对模式串 $P$，定义

$$
\mathrm{next}[i]=\max\{\,k\le i \mid P[0..k-1]=P[i-k+1..i]\,\},
$$

即 $P[0..i]$ 的**最长 border 长度**——既是真前缀又是真后缀的最长子串的长度，不存在这样的前后缀时为 $0$。"真"表示不能取整个子串本身，所以 $k\le i$ 而不是 $k\le i+1$。

例：$P=$ `abcac` 时 $\mathrm{next}=[0,0,0,1,0]$。

| $i$ | $P[i]$ | $\mathrm{next}[i]$ | 说明 |
|---|---|---|---|
| 0 | a | 0 | 真前缀不存在 |
| 1 | b | 0 | `a` 与 `b` 不等 |
| 2 | c | 0 | `ab` 与 `bc` 不等 |
| 3 | a | 1 | 前缀 `a` 与后缀 `a` 相同 |
| 4 | c | 0 | `a` 与 `c` 不等，回退后仍不等 |

### 5.9.2 构造

从左到右扫描，用 $k$ 记录**上一位**的 border 长度：

```cpp
void buildNext(const std::string &P, std::vector<int> &nxt) {
    int m = P.size();
    nxt.assign(m, 0);
    int k = 0;                       // 当前 border 长度
    for (int i = 1; i < m; ++i) {
        while (k > 0 && P[i] != P[k]) k = nxt[k - 1];   // 沿 border 链回退
        if (P[i] == P[k]) ++k;
        nxt[i] = k;
    }
}
```

**为什么回退用 `nxt[k-1]` 而不是 `nxt[k]`**：$k$ 是"当前候选 border 的长度"，它对应前缀 $P[0..k-1]$。当 $P[i]\ne P[k]$ 时，需要找一个更短的 border，而"$P[0..k-1]$ 的最长 border"正是 `nxt[k-1]`（下标 $k-1$ 对应长度 $k$ 的前缀的最后一个字符）。**长度与下标差一，是 everywhere 的错源。**

**复杂度**：$k$ 只在 `if` 成功时 $+1$，总共增加不超过 $m$ 次；每次回退使 $k$ 严格减小，故回退总次数也不超过 $m$。于是构造是 $O(m)$。

### 5.9.3 匹配

```cpp
int kmpMatch(const std::string &T, const std::string &P) {
    int n = T.size(), m = P.size();
    if (m == 0) return 0;
    if (m > n) return -1;
    std::vector<int> nxt;  buildNext(P, nxt);
    int j = 0;                                  // 已匹配的前缀长度
    for (int i = 0; i < n; ++i) {
        while (j > 0 && T[i] != P[j]) j = nxt[j - 1];
        if (T[i] == P[j]) ++j;
        if (j == m) return i - m + 1;
    }
    return -1;
}
```

失配时执行 $j\leftarrow \mathrm{next}[j-1]$，再比较 $T[i]$ 与 $P[j]$。**注意下标**：失配时已匹配 $j$ 个字符，要用的是 $\mathrm{next}[j-1]$，而非 $\mathrm{next}[j]$。

**匹配为什么是 $O(n)$**：$i$ 每轮 $+1$，不回退；$j$ 每轮最多 $+1$，故 $j$ 的总增加量不超过 $n$；每次回退使 $j$ 至少 $-1$，故回退总次数也不超过 $n$。$i$ 的推进与 $j$ 的增减都各只有 $O(n)$ 次，总代价 $O(n)$。

### 5.9.4 完整跟踪

$T=$ `ababcabcacbab`、$P=$ `abcac`、$\mathrm{next}=[0,0,0,1,0]$：

| $i$ | $T[i]$ | 回退前 $j$ | 动作 | 本轮结束 $j$ | 说明 |
|---|---|---|---|---|---|
| 0 | a | 0 | 无 | 1 | 配上 `a` |
| 1 | b | 1 | 无 | 2 | 配上 `ab` |
| 2 | a | 2 | $\mathrm{next}[1]=0$ | 1 | `a`×`c` 失配，重新用 `a` 配 |
| 3 | b | 1 | 无 | 2 | 配上 `ab` |
| 4 | c | 2 | 无 | 3 | 配上 `abc` |
| 5 | a | 3 | 无 | 4 | 配上 `abca` |
| 6 | b | 4 | $\mathrm{next}[3]=1$ | 2 | `b`×`c` 失配，保留后缀 `a` |
| 7 | c | 2 | 无 | 3 | 配上 `abc` |
| 8 | a | 3 | 无 | 4 | 配上 `abca` |
| 9 | c | 4 | 无 | 5 | $j=m$，返回 $9-5+1=5$ |

> **要点** 第 6 行是关键：已匹配 `abca`，它的最长 border 是 `a`（长度 1），所以回退后只保留 **1 个字符**，`j` 从 4 变成 2（因为下一步还要比 $P[1]$）。这里如果记成"保留 `ab`"就是错的——`ab` 是 `abca` 的**前缀**但不是**后缀**。

### 5.9.5 改进的 next：nextval

既然失配时 $T[i]\ne P[j]$，如果回退到的那个字符 $P[\mathrm{next}[j]]$ 恰好**等于** $P[j]$，那么这次比较**必然再次失败**，白白多比一次。nextval 把这层"连续相同字符"压掉。

教材（1 基）写法，$\mathrm{next}[1]=0$：

$$
\mathrm{nextval}[j]=
\begin{cases}
0, & j=1,\\
\mathrm{nextval}\big[\mathrm{next}[j]\big], & P[j]=P[\mathrm{next}[j]],\\
\mathrm{next}[j], & P[j]\ne P[\mathrm{next}[j]].
\end{cases}
$$

两个例子都验算过：

| 模式串 | `next`（1 基） | `nextval` | 效果 |
|---|---|---|---|
| `abcac` | $0,1,1,1,2$ | $0,1,1,0,2$ | 第 4 位从 $1$ 降到 $0$，省掉一次必然失败的比较 |
| `aaaab` | $0,1,2,3,4$ | $0,0,0,0,4$ | 前四位全压成 $0$，一次失配后的连比从最多 $4$ 次降到 $1$ 次 |

`aaaab` 这一例说明 nextval 省的是**每次失配后的连续回退**：只用 `next` 时，第 5 位失配要沿 $4\to3\to2\to1\to0$ 连比四次（每次都拿 `a` 去撞同一个失配字符）；用 `nextval` 一次跳到 $0$。

> **要点** nextval 只是**常数因子**的改进。只用 `next` 的 KMP 已经是 $O(n+m)$（回退总次数被"$j$ 的增加次数"限制住），nextval 让实际比较次数更贴近这个界，但没有改变渐近阶。模式串自身高度重复时，这个常数可以差到 $m$ 倍。

## 5.10 复杂度与选型

| 方面 | 朴素匹配 | KMP |
|---|---|---|
| 预处理 | 无 | next 数组，$O(m)$ |
| 匹配时间 | 最坏 $O(nm)$，期望 $O(n)$ | 最坏 $O(n+m)$ |
| 主串指针 | 会回退 | 永不回退 |
| 额外空间 | $O(1)$ | $O(m)$ |
| 适用 | 短串、一次性查找 | 长文本、模式重复度高 |

next 数组只依赖模式串，可预先算一次、供多个文本复用——文本量越大、模式越固定，KMP 的相对优势越明显。

**其他选择**：

- 字母表很大或模式较长：Boyer–Moore 能按坏字符/好后缀**跳跃**，实际比 KMP 快 3–5 倍；
- 同时匹配多个模式：Aho–Corasick（字典树 + 失配链，本质是 KMP 的多模式版）；
- 允许近似匹配：编辑距离（动态规划）或位并行算法；
- 索引级需求（反复查询同一文本）：后缀数组 / 后缀自动机，预处理 $O(n)$ 后单次查询 $O(m)$。

> **要点** 所有串匹配算法的共同思路是**把已经付出代价换来的信息保存下来复用**：KMP 保存"已匹配前缀的 border 结构"，BM 保存"后缀比较的结果"，AC 保存"多个模式的前缀集合"。这是这一讲真正可迁移的教训。

## 订正

1. **朴素匹配的比较次数表少算一次。** 课件给"$2+1+5+1+1+5=15$"，但起点 $i=0$ 处实际比较了 3 次：`a`✓、`b`✓、`a`×`c`。表格的"Compared characters"一列对 $i=0$ 只列了**命中的两个字符**（`a b`），对 $i=2$ 却把**失配的字符也列进去**了（`a b c a b` 五个），口径不一致，于是总数少了 1。**正确值：$3+1+5+1+1+5=16$。** 5.7 已按逐起点的方式重列。
2. **KMP 跟踪表漏了一行，并且把"保留的后缀"写错。** 课件表从 $i=0$ 直接跳到 $i=2$，缺 $i=1$ 那一行（$T[1]=$ `b` 与 $P[0]=$ `a` 失配，$j$ 保持 $0$）。更要紧的是 $i=6$ 那行注"keep suffix `ab`"——已匹配的是 `abca`，$\mathrm{next}[3]=1$，保留的是**一个字符 `a`**，不是 `ab`。`ab` 是 `abca` 的前缀但不是它的后缀，若按 `ab` 理解，后续 `j` 会算成 3 而实际是 2，整条跟踪就错位。
3. **`next` 定义写成 $k<i+1$。** 这在整数上等价于 $k\le i$，但与"真前缀"的直觉对不上：$k\le i$ 读起来就是"不能取整个子串"。课件同页文字说"proper means the prefix cannot be the whole substring"，公式却没体现这个约束的直观形式。5.9.1 改成 $k\le i$。
4. **构造 next 时 $i=4$ 的说明跳过了 $k=1$ 那一步。** 课件写"candidate `ab` fails, so fall back to `next[0]=0`"，实际回退链是 $k=4\to\mathrm{next}[3]=1\to\mathrm{next}[0]=0$：先比 `c` 与 `b` 失败，再比 `c` 与 `a` 失败，才得到 $0$。省略掉的这一跳恰恰是"回退链使构造线性"的例证，不能省。
5. **课件通篇用 0 基 next（`next[i]` 是以 $i$ 结尾子串的 border 长度，失配回退 `next[j-1]`），教材用 1 基（`next[j]` 是第 $j$ 个字符失配时应对齐的位置，`next[1]=0`）。** 换算关系是

   $\mathrm{next}_{\text{教材}}[j+1]=\mathrm{next}_{\text{本篇}}[j]+1\ (j\ge1)$，且 $\mathrm{next}_{\text{教材}}[1]=0$、$\mathrm{next}_{\text{教材}}[2]=1$。

   以 `abcac` 验算：本篇 $[0,0,0,1,0]$，教材 $[0,1,1,1,2]$，逐位对得上。**注意不是"整体加一"那么简单**：教材的 `next[1]` 单独特判为 $0$，且下标整体错一位，直接加一会让 `next[1]` 变成 $1$。5.9.5 的 nextval 用的是教材 1 基口径，与本篇的 0 基 next 属于不同体系，**不能混着套**。
6. **课件第 27 页的"最坏情况"用「空内联公式」写变量**——两个美元符号成对出现、中间只写了 `T = `，导出后美元符号原样印在页面上。属排版问题，不影响结论；但读到页面上孤零零的美元符号时别把它当成符号本身的一部分。
