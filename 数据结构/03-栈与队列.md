# 03 栈与队列

> 系列：[[01-数据结构与算法概论]] · [[02-1-线性表·顺序表]] · [[02-2-线性表·链表]] · [[03-栈与队列]] · [[04-串]] · [[05-数组与特殊矩阵]]

线性表可以随便插、随便删、随便读。这一讲开始**限制操作的位置**：栈只动一端，队列两端各管一头，优先级队列按关键字出。限制带来的回报是——三种容器的每个核心操作都能压到 $O(1)$，而不需要任何额外结构。

三者都是线性表的**受限期**（restricted linear list）：底层还是那条表，只是把"任意位置"收窄成"规定位置"。

## 4.1 栈：定义与 ADT

**定义 4.1.1（栈）** 栈是只允许在一端（**栈顶 top**）进行插入与删除的线性表，另一端称为**栈底（bottom）**。

操作原则是**后进先出**（LIFO，Last In First Out）：最后压入的元素最先弹出。

| 操作 | 功能 | 代价 |
|---|---|---|
| `InitStack` / `StackEmpty` | 初始化、判空 | $O(1)$ |
| `Push` | 在栈顶插入 | $O(1)$ |
| `Pop` | 删除并返回栈顶 | $O(1)$ |
| `GetTop` | 读栈顶，不删除 | $O(1)$ |

空栈执行 `Pop` 为**下溢（underflow）**，满栈执行 `Push` 为**上溢（overflow）**。两者都是**可恢复的失败**，必须检查并返回状态，不能当成错误直接退出。

> **要点** 栈的全部价值在一条不变量：**栈顶永远是"最近一个尚未处理完的元素"**。凡是求解过程中出现"最后遇到的条件要先结算"的场景，栈就是天然匹配的结构——括号匹配、表达式求值、函数调用、DFS、回溯、撤销。

## 4.2 顺序栈

用数组存放，`top` 记录**栈顶元素的下标**而非元素个数：

- 空栈：`top = -1`
- 有一个元素：`top = 0`
- 下一个空位：`top + 1`

```cpp
struct SqStack {
    int  data[MAX];
    int  top;          // -1 表示空栈
};

bool Push(SqStack &S, int x) {
    if (S.top == MAX - 1) return false;   // 上溢
    S.data[++S.top] = x;
    return true;
}

bool Pop(SqStack &S, int &x) {
    if (S.top == -1) return false;        // 下溢
    x = S.data[S.top--];
    return true;
}
```

三种操作都只动一端，**无元素移动**，$O(1)$。容量固定，上溢是真实风险——这是顺序栈唯一的短板。

> **补充（两种 top 约定）** 教材（严蔚敏）的顺序栈用 `top` 指向**栈顶元素的下一个空位**，初值 `top = base`。于是判空是 `top == base`，判满是 `top - base == stacksize`，`Push` 先写 `*top++ = x` 再判满要提前做。两种写法功能等价，但**判空判满的条件、以及 `top` 的语义完全相反**，答题和读别人的代码时必须先确认是哪一种。本篇统一用"`top` 是下标、`-1` 为空"这一套（与课件一致）。

## 4.3 链栈

以单链表的**表头为栈顶**：入栈即头插，出栈即删首结点，两者都是 $O(1)$，且**无容量上限**。

```cpp
struct LNode {
    int   data;
    LNode *next;
};

bool Push(LNode *&top, int x) {
    LNode *s = new LNode{x, top};
    top = s;
    return true;
}

bool Pop(LNode *&top, int &x) {
    if (!top) return false;
    LNode *p = top;
    x = p->data;
    top = p->next;
    delete p;
    return true;
}
```

链栈**不需要头结点**：头指针本身为 `nullptr` 就表示空栈，判空只需一次比较。

**两条顺序不能颠倒**：入栈必须**先**让新结点指向原栈顶，**再**改栈顶指针（否则原链丢失）；出栈必须**先**读值、**再**改指针、**最后**释放结点（否则读的是已释放内存）。

栈底是尾结点，永远不必访问——这正是链栈不需要尾指针的原因。

## 4.4 顺序栈与链栈的对比

| 方面 | 顺序栈 | 链栈 |
|---|---|---|
| 存储 | 一块连续空间 | 堆上结点加指针 |
| 容量 | 固定 `MAX` | 受内存限制 |
| 溢出 | 显式判满，可恢复 | `new` 失败抛异常 |
| 入栈出栈 | $O(1)$ | $O(1)$ 加分配开销 |
| 空间开销 | 每元素无额外开销 | 每结点一个指针 |
| 适用 | 深度小且稳定 | 深度不可预测 |

两者遵循同一个 ADT，差别只在**失败方式**与**常数因子**。

## 4.5 应用一：括号匹配

**思想**：右括号必须与**最近的**未匹配左括号配对，这正是 LIFO。扫描一遍，遇左括号入栈，遇右括号检查栈顶并出栈，忽略其他字符，最后要求栈空。

**失败只有三种**：

1. **栈空遇右括号**（下溢）——右括号多余；
2. **出栈的左括号与右括号类型不符**——交叉嵌套；
3. **扫描结束栈非空**——左括号多余（有剩余）。

长度为 $n$ 的时间 $O(n)$，空间最坏 $O(n)$（全为左括号时），一般等于嵌套深度。

> **补充（为什么不能只用计数器）** 若只有一种括号，一个计数器就够：遇左加一、遇右减一、中途不得为负、末尾必须为零。一旦出现多种括号，"数量相等"就不再等价于"配对合法"——`([)]` 中两种括号各一对、计数器全程非负，却是非法的。计数器只记得**数量**，栈记得**顺序**，这是栈不可替代的地方。

## 4.6 应用二：表达式求值

两种经典做法，都依赖栈：

- **双栈法**：操作数栈与运算符栈各一；遇右括号弹出运算符直到左括号，每次对一个运算符取两个操作数计算。
- **中转后缀再求值**：输出操作数；运算符入栈时先弹出所有优先级**不低于**它的栈顶；遇括号按分隔符处理；后缀式再从左到右用操作数栈求值。

例：$3+4\times2$ 的后缀式为 `3 4 2 * +`，求值得 $11$。

> **补充（中缀转后缀的完整规则）** 设当前读入运算符 $op$：
>
> 1. 若 $op$ 是操作数：直接输出；
> 2. 若 $op$ 是 `(`：入栈；
> 3. 若 $op$ 是 `)`：弹栈并输出，直到弹出 `(`（`(` 不输出）；
> 4. 若 $op$ 是二元运算符：当栈非空、栈顶不是 `(`、且**栈顶优先级 $\ge$ 当前优先级**时，反复弹出并输出；然后把 $op$ 入栈；
> 5. 读完输入后，把栈中剩余运算符全部弹出输出。
>
> 第 4 条里的「$\ge$」是**左结合**的体现：$3-4-5$ 应为 $(3-4)-5=-6$，后缀是 `3 4 - 5 -`；若误用「$>$」就变成右结合的后缀 `3 4 5 - -`，算出来是 $3-(4-5)=4$，错得很离谱。再如 $8/4/2$：正确是 `8 4 / 2 /` $=1$，右结合 `8 4 2 / /` 则是 $8/(4/2)=4$。**只有幂运算（右结合）才用「$>$」。**

## 4.7 队列：定义与 ADT

**定义 4.7.1（队列）** 队列只允许在**队尾（rear）插入**、在**队头（front）删除**的线性表，原则为**先进先出**（FIFO）。

`InitQueue`、`QueueEmpty`、`Enqueue`、`Dequeue`、`GetFront` 均为 $O(1)$。空队出队为下溢；定容队列满时入队失败。

队列是栈的"公平"对偶：最早进入的元素最先离开。典型用途为打印队列、任务调度、BFS。

## 4.8 顺序队列与假溢出

朴素数组队列用 `front` 指向首元素、`rear` 指向下一个空位，入队 `rear++`、出队 `front++`。

以 `MAX = 6` 为例，四步走：

| 步骤 | 操作 | `front` | `rear` | 内容 |
|---|---|---|---|---|
| 0 | 初始 | 0 | 0 | `_ _ _ _ _ _` |
| 1 | 入队 10,20,30,40 | 0 | 4 | `10 20 30 40 _ _` |
| 2 | 出队 10,20 | 2 | 4 | `_ _ 30 40 _ _` |
| 3 | 入队 50,60 | 2 | 6 | `_ _ 30 40 50 60` |

第 3 步后 `rear == MAX`，此时再入队 70 会失败，而 0、1 两个单元其实空着。

**假溢出（false overflow）**：数组没满，只是 `rear` 走到了末尾。注意"入队 4 个再出队 2 个"**不构成**这个场景——那时 `rear = 4`，下一个格子还空着；必须再入队 2 个把 `rear` 顶到 `MAX` 才会失败。

解法是让下标**循环回绕**。

## 4.9 循环队列

把 `data[0..MAX-1]` 看成环，出队后

$$
front=(front+1)\bmod \text{MAX},
$$

入队后

$$
rear=(rear+1)\bmod \text{MAX}.
$$

被释放的队头单元可在队尾复用，两端都不搬移元素。

**四个不变量必须成套记住**：

| 不变量 | 公式 |
|---|---|
| 空 | $front=rear$ |
| 满 | $(rear+1)\bmod \text{MAX}=front$ |
| 长度 | $(rear-front+\text{MAX})\bmod \text{MAX}$ |
| 容量 | 至多 $\text{MAX}-1$ 个元素 |

满与空之所以能区分，靠的是**牺牲一个单元**：`rear` 是下一个写入位置，因此 `front` 前面那个格子永远空着。若不愿牺牲，可另存元素个数 `size` 或设 `tag` 标志。

> **补充（长度公式的证明）** 设 `front`、`rear` 都在 $[0,\text{MAX})$ 内。队列中的元素恰好是从 `front` 开始、沿顺时针方向、不越过 `rear` 的那一段，共 $d$ 个，于是 $rear\equiv front+d \pmod{\text{MAX}}$，即 $d\equiv rear-front\pmod{\text{MAX}}$。因为 $0\le d\le \text{MAX}-1$，$d$ 就是 $rear-front$ 模 $\text{MAX}$ 的**最小非负余数**，也就是 $(rear-front+\text{MAX})\bmod\text{MAX}$。$\square$
>
> **三种易错点**：
>
> 1. 把 `rear` 当作"最后一个元素"而非"下一个空位"——判满式随之改变；
> 2. 求长度时漏掉 `+ MAX`（C++ 负数取模仍为负）；
> 3. 把 `front = rear` 当成满（在牺牲一格的约定下它是空）。
>
> **退化情形**：`MAX = 1` 时队列容量为 $0$，`front == rear` 恒成立，这个队列永远既空又满。定容循环队列要求 `MAX ≥ 2`。

## 4.10 链队列

设 `front` 与 `rear` 两个指针，队头出队、队尾入队，两端均 $O(1)$。若没有 `rear`，每次入队都要走到表尾，退化为 $O(n)$。

**两处必须特殊处理**：

- 空队入队时，`front` 与 `rear` **同时**指向新结点；
- 出队删掉最后一个结点后，`front` 变为空，此时**必须同时把 `rear` 置空**，否则下次入队会通过悬垂指针写入。

> **补充（带头结点的链队列）** 教材版链队列带一个头结点，`front` 指向头结点、`rear` 指向尾结点。这样"空队"是 `front == rear`，入队出队都不必判空特例，代价是多一个结点和一次 `new`。不带头的版本更省，但上面两条特判不能漏——考试里两种都出现过，看题干有没有画那个"空结点"。

## 4.11 循环队列与链队列的对比

| 方面 | 循环队列 | 链队列 |
|---|---|---|
| 存储 | 定长数组，取模复用 | 堆上结点加指针 |
| 容量 | `MAX - 1`，溢出即错误 | 受内存限制 |
| 入队出队 | $O(1)$ | $O(1)$ 加分配开销 |
| 空间开销 | 一个被牺牲的单元 | 每结点一个指针 |
| 边界 | 满空歧义、取模 | 空队重置、单结点重置 |
| 适用 | 有界缓冲、嵌入式 | 长度不可预测 |

## 4.12 优先级队列与二叉堆

### 4.12.1 定义与 ADT

**定义 4.12.1（优先级队列）** 存放带**关键字（key）**的元素，出队的永远是**关键字最优**的那一个，与到达顺序无关。取最小者称最小优先级队列，取最大者称最大优先级队列。

关键字相同时的次序默认任意；需要稳定则另加序号字段。

**对比**：栈取最新的，队列取最早的，优先级队列取**最优的**。队列可视为"所有 key 相等、以到达顺序打破平局"的特殊情形。

| 操作 | 功能 | 二叉堆下的代价 |
|---|---|---|
| `Insert` | 插入元素及其关键字 | $O(\log n)$ |
| `ExtractMin` | 删除并返回最小关键字 | $O(\log n)$ |
| `Min` | 读最小关键字，不删除 | $O(1)$ |
| `Empty` / `Size` | 判空、元素个数 | $O(1)$ |

Dijkstra 所需的 `DecreaseKey` 在堆上为 $O(\log n)$（需知道元素下标）。ADT **不要求**有序遍历与按值查找，正是这一限制使堆可以高效。

> **要点** 优先级队列是一族 ADT，不是一种结构。同一个"取最小"的接口，用无序数组、有序数组、二叉堆、平衡树、斐波那契堆实现，代价完全不同。"选实现"就是"选哪个操作要快"。

### 4.12.2 实现方式对比

| 表示 | `Insert` | `ExtractMin` | `Min` | 说明 |
|---|---|---|---|---|
| 无序数组 | $O(1)$ | $O(n)$ | $O(n)$ | 最简单，出队时扫描 |
| 有序数组 | $O(n)$ | $O(1)$ | $O(1)$ | 入队时保持有序 |
| 二叉堆 | $O(\log n)$ | $O(\log n)$ | $O(1)$ | 通用最优 |
| 平衡 BST | $O(\log n)$ | $O(\log n)$ | $O(\log n)$ | 还能有序遍历 |
| 斐波那契堆 | $O(1)$ 均摊 | $O(\log n)$ | $O(1)$ | 适合 `DecreaseKey` |

### 4.12.3 二叉小顶堆

**形状性质**：完全二叉树，除最后一层外每层填满，最后一层从左到右填。

**堆序性**：每个结点不大于其孩子，故最小值必在根。

用数组存储（0 基），下标关系为

$$
\text{左孩子}=2i+1,\qquad \text{右孩子}=2i+2,\qquad \text{父}=\left\lfloor\frac{i-1}{2}\right\rfloor .
$$

> **补充（为什么 0 基是这三个式子）** 完全二叉树按层序编号后，第 $k$ 层（从 $0$ 计）有 $2^k$ 个结点，前 $k$ 层共 $2^k-1$ 个。设结点 `i` 在第 $k$ 层，则该层首结点的下标为 $2^k-1$，它在层内的偏移是 $i-(2^k-1)$。它左孩子在下一层的偏移是 $2\big(i-(2^k-1)\big)$，而下层首结点下标是 $2^{k+1}-1$，于是左孩子下标为 $2^{k+1}-1+2i-2^{k+1}+2=2i+1$，右孩子再加一。父公式是左孩子公式的反解。

堆是**部分有序**而非有序：兄弟之间没有固定关系，因此不能有序遍历，也不能二分查找。

**插入（上滤 sift up）**：先放到数组末尾以保持形状，再与父结点比较，比父小就交换，直到不再违反堆序。只有新叶子到根这一条路径可能失序，故最多交换 $\lfloor\log_2 n\rfloor$ 次，$O(\log n)$。

**取最小（下滤 sift down）**：先取出根上的最小值，把**最后一个叶子**移到根以保持形状，再与**较小的那个孩子**交换，逐层下移。必须选较小的孩子，否则换上来仍大于另一个孩子。$O(\log n)$。

**建堆**：对数组从最后一个非叶结点 $\lfloor n/2\rfloor-1$ 起，自后向前、自下而上逐个下滤。叶子本身已是合法堆，处理 $i$ 时它的两棵子树都已成堆。

### 4.12.4 建堆为什么是线性的

高度为 $h$ 的结点下滤至多 $h$ 层。完全二叉树中高度为 $h$ 的结点恰有 $\lceil n/2^{h+1}\rceil$ 个，且 $\lceil n/2^{h+1}\rceil\le n/2^{h}$，故总代价

$$
T(n)=\sum_{h=0}^{\lfloor\log_2 n\rfloor}h\left\lceil \frac{n}{2^{h+1}}\right\rceil
\le \sum_{h=0}^{\infty}\frac{n\,h}{2^{h}}=n\cdot 2=2n=O(n).
$$

其中 $\sum_{h\ge0}h/2^h=2$ 由 $\sum_{h\ge0}hx^h=x/(1-x)^2$ 取 $x=1/2$ 得到。

直观上：一半结点是叶子（零工作），四分之一只下滤一层，八分之一两层……昂贵的层数很少，故总和线性。

> **补充（为什么不能自顶向下上滤建堆）** 逐个 `Insert` 也能建堆，每次上滤 $O(\log n)$，总共 $O(n\log n)$。差别在于**工作量分布**：上滤的代价等于结点的**深度**，而完全二叉树里深的结点占多数（一半在最底层），于是总代价 $\sum_{\text{结点}} \text{深度}=\Theta(n\log n)$；下滤的代价等于结点的**高度**，高的结点极少（根只有一个），总代价 $\Theta(n)$。**同一个"逐层调整"的想法，从哪一头做起决定了复杂度**——这是堆这一节最值钱的一句话。

### 4.12.5 标准库的默认值是个坑

`std::priority_queue<int>` 是**大顶堆**（默认 `less<int>`），要小顶堆需显式写：

```cpp
std::priority_queue<int, std::vector<int>, std::greater<int>> pq;  // 小顶堆
```

## 4.13 案例：两个栈实现队列

一个栈无法直接做队列：它的顶是最新元素，而队列需要最旧元素。两个栈靠**反转两次**解决：`in` 接收新元素，`out` 保存已反转的元素，其栈顶即队头。

### 4.13.1 方案一：慢入队、快出队

每次入队都把 `in` 全部倒入 `out`，压入新元素后再全部倒回 `in`，使 `in` 始终按队列顺序、队头在栈顶。于是 `pop`、`peek`、`empty` 都是 $O(1)$，而一次入队要搬动全部元素，为 $O(n)$。

只适合出队远多于入队的负载。

### 4.13.2 方案二：快入队、懒转移

入队只压入 `in`，$O(1)$。出队时**仅当 `out` 为空**，才把 `in` 逐个弹出并压入 `out`（一次反转），再从 `out` 弹出。`peek` 同样要先做这次转移。判空需检查两个栈（或维护计数）。

关键规则是"**只在 `out` 空时转移**"：已在 `out` 中的元素一定比 `in` 中的所有元素更早到达，必须先离开；若 `out` 非空还去搬，就破坏了这个次序。

**均摊分析**：$n$ 次入队使每个元素进 `in` 一次（$n$ 次操作）；每个元素至多从 `in` 移到 `out` 一次（至多 $n$ 次）；每个元素从 `out` 弹出一次（$n$ 次）。总计 $O(n)$ 对应 $2n$ 次队列操作，故单次均摊 $O(1)$。

| 指标 | 代价 |
|---|---|
| `push` | $O(1)$ 最坏 |
| `pop` / `peek` | $O(1)$ 均摊；$O(n)$ 最坏（那一次转移） |
| 空间 | 两栈合计 $O(n)$ |
| 额外指针 | 无 |

"均摊"不是"平均情况"：单次 `pop` 仍可能很贵，但**贵的转移对每个元素至多发生一次**。

**陷阱**：

| 陷阱 | 后果 |
|---|---|
| 每次出队都转移 | 单次 $O(n)$，失去均摊 |
| `peek` 忘记转移 | 读到错误的队头 |
| 只检查 `in` 判空 | `out` 还有元素却报空 |
| 往 `out` 里压新元素 | 破坏 FIFO，新元素插队 |
| 只搬 `in` 的一部分 | 两批混在一起，次序错乱 |

## 4.14 容器选择

| 需求 | 容器 | 理由 |
|---|---|---|
| 要最近加入的元素 | 栈 | LIFO，两端 $O(1)$ |
| 要按到达顺序处理 | 队列 | FIFO，两端 $O(1)$ |
| 要最优关键字 | 优先级队列 | 堆把极值放在根 |
| 要按下标随机访问 | 顺序表 | 地址计算 $O(1)$ |
| 要频繁任意位置插删 | 链表 | 已知结点处 $O(1)$ 改链 |

先问四个问题：下一个该取走谁（最新／最早／最优）？规模是否有界？是否需要有序遍历？是否需要稳定？答案定下 ADT，再定存储。

## 订正

1. **顺序栈的 `top` 有两套约定，课件只给了一套。** 课件用"`top` 是栈顶下标，`-1` 为空"，教材用"`top` 指向栈顶的下一个空位，初值为 `base`"。两者的**判空、判满、`Push` 的写法全相反**（课件判满 `top == MAX-1`，教材判满 `top - base == stacksize`）。4.2 已把两套并列写出；考试若只写一套，先声明约定，否则一半的判据会被判错。
2. **课件"建堆是线性的"那段，文字与公式口径不一致。** 文字说"高度为 $h$ 的结点至多 $\lceil n/2^{h+1}\rceil$ 个"（正确），公式却写成 $\sum \frac{n}{2^{h+1}}h$ 并据此得出 $T(n)\le n$（把取整扔掉了）。$n=7$ 的满二叉树叶结点有 $4$ 个而 $n/2 = 3.5$，取整不能省。正确写法是 $T(n)=\sum h\lceil n/2^{h+1}\rceil\le \sum h\,n/2^{h}=2n=O(n)$，**结论 $O(n)$ 不变，常数上界要放宽到 $2n$**。4.12.4 已按正确写法给出。
3. **课件"四个不变量"表把容量列进"公式"列**（"至多 `MAX-1` 个元素"），前三行是等式、第四行是上界，混在一起容易被当成同一类。容量是**由判满式推出的结论**，不是独立成立的等式：`(rear+1) % MAX == front` 与"最多 `MAX-1` 个"是同一件事的两种说法。
4. **`std::priority_queue` 默认是大顶堆，正文讲的是小顶堆。** 课件把两者放在相邻两页，代码却只改了模板参数没说清"语义整体反过来"。直接拿小顶堆的下标公式去解释 `std::priority_queue` 的行为会得到相反结论——`ExtractMin` 对应的是 `top()` 取**最大**元素。
5. **"两个栈实现队列"的均摊结论依赖"只在 `out` 空时转移"，而课件把这条规则和实现放在两页**，读的时候容易只记住"入队压 `in`、出队弹 `out`"而漏掉转移条件——漏掉它，出队就会读到错误的元素，复杂度也变成 $O(n)$。
6. **链栈、链队列都省略了头结点**，与 [[02-2-线性表·链表]] 里"教材带头结点"的口径不一致。判空与首结点特判因此全部不同，见 4.3 与 4.10 的补充。
