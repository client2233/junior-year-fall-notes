## 公式排查与规范化（同日，第二轮）

小水滴反馈「md 公式有问题」，做了穷举排查 + 加固。改稿前原稿备份在 `.workbuddy/tmp/fa_backup_20260928/`。

**排查结论：LaTeX 语法本身零错误。** 1647 个公式（149 个块 + 1498 个行内），KaTeX 与 MathJax 双引擎逐条渲染、display/inline 双模式各一遍，**0 报错**；定界符配对 100%（「公式数 × 2」恰好等于单 `$` 总数）；无 BOM / CRLF / 零宽字符；`\tag` 编号与教材逐条一致。

**真正的病根在 Markdown 层，三类脆弱写法：**
1. **52 处块级公式紧贴上一行文字**（`$$` 前无空行）—— Obsidian 官方要求 `$$` 独占行且前后空行，这是公式不渲染的头号原因。原稿 04 一篇就占 19 处。
2. **134 个单行 `$$公式$$`** —— Obsidian 按行内模式处理，其中 15 个含 `\tag` / `\begin{cases}` / `\\`，这些在行内模式下会失效。
3. **表格内 `\|`（05 速查表 8 处）** —— `|` 是 Markdown 表格分隔符，虽可反斜杠转义但脆弱。

**修复内容**：`\|` → `\lVert …\rVert`（424 处）；单行块 → 标准三行块；全部块前后补空行。文件 1109 → 1645 行。

**踩到的坑（重要）**：`\|x\|` 批量替换成 `\lVert x\rVert` 时，`\lVert` 会直接咬住后面的字母变成未定义控制序列 `\lVertx` —— 一次产生 **184 处**黏连。肉眼完全看不出来，是 KaTeX 渲染校验抓出来的。修法是 `\lVert` 后紧跟字母/数字时补一个空格。**教训：公式改动必须跑真渲染器验证，定界符计数为偶毫无意义。**
